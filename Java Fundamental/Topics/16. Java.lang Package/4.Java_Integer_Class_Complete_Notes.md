# Java `Integer` Class 

## 1. What is the `Integer` class?

`Integer` is a wrapper class in `java.lang` that represents a primitive
`int` value as an object.

``` java
int primitive = 25;
Integer object = Integer.valueOf(25);
```

-   `int` is a primitive type; it stores an integer value directly.
-   `Integer` is a reference type; a variable of this type refers to an
    object that represents an integer.
-   `Integer` is `final`, so it cannot be subclassed.
-   `Integer` extends `Number` and implements `Comparable<Integer>`,
    `Serializable`, and `Constable` (modern Java versions).
-   Its value is immutable: after an `Integer` object is created, its
    represented value cannot be changed.

The class is in `java.lang`, so no import is required.

## 2. `int` vs `Integer`

  -----------------------------------------------------------------------
  Feature                 `int`                   `Integer`
  ----------------------- ----------------------- -----------------------
  Kind                    Primitive               Wrapper class

  Can be `null`           No                      Yes

  Default field value     `0`                     `null`

  Useful for arithmetic   Directly                Usually unboxed first

  Can be used as a        No                      Yes
  generic type argument

  `parseInt()`                                    

  Memory/overhead         Usually lower           Object/reference
                                                  overhead may apply

Example:

``` java
int a = 10;
Integer b = 10; // autoboxing
int c = b;      // unboxing
```

**Important:** `Integer` is not simply a more powerful `int`. Use `int`
by default for ordinary numeric calculations; use `Integer` when an
object is required or `null` has meaning.

## 3. Autoboxing and unboxing

### Autoboxing

The compiler automatically converts an `int` to an `Integer`.

``` java
Integer x = 50;
// Conceptually similar to:
Integer y = Integer.valueOf(50);
```

### Unboxing

The compiler automatically converts an `Integer` to an `int`.

``` java
Integer x = 50;
int y = x.intValue(); // explicit equivalent of unboxing
```

Unboxing a `null` reference throws `NullPointerException`:

``` java
Integer x = null;
// int y = x; // NullPointerException at runtime
```

Check for `null` before unboxing when the reference may be absent.

Autoboxing/unboxing can also happen in assignments, method calls,
returns, and expressions. It is convenient, but repeated boxing in
performance-sensitive code can create overhead.

## 4. Creating `Integer` values

### Preferred approaches

``` java
Integer a = Integer.valueOf(100);
Integer b = Integer.valueOf("100");
Integer c = 100; // autoboxing
```

`Integer.valueOf(...)` is generally preferred to constructing an object
manually.

### Avoid the deprecated constructor

``` java
Integer x = new Integer(100); // deprecated since Java 9
```

The constructor is deprecated because factory methods such as
`valueOf()` can reuse cached objects. Do not use `new Integer(...)` in
new code.

## 5. Important constants / fields

### `Integer.MIN_VALUE`

The smallest possible `int` value: `-2,147,483,648`.

### `Integer.MAX_VALUE`

The largest possible `int` value: `2,147,483,647`.

### `Integer.SIZE`

The number of bits in the binary representation of an `int`: `32`.

### `Integer.BYTES`

The number of bytes used to represent an `int`: `4`.

### `Integer.TYPE`

The `Class` object representing primitive type `int`.

``` java
System.out.println(Integer.MIN_VALUE);
System.out.println(Integer.MAX_VALUE);
System.out.println(Integer.SIZE);  // 32
System.out.println(Integer.BYTES); // 4
System.out.println(Integer.TYPE);  // int
```

`int` is a signed 32-bit two's-complement integer. Its range is from
`-2^31` to `2^31 - 1`.

## 6. Parsing and converting strings

These methods are commonly confused. **Parsing** converts text into a
primitive number; **valueOf** returns an `Integer` object.

### `parseInt(String s)`

Parses a decimal string and returns primitive `int`.

``` java
int n = Integer.parseInt("123");
```

Throws `NumberFormatException` if the text is not a valid integer or is
outside the `int` range.

``` java
// Integer.parseInt("12.5"); // NumberFormatException
// Integer.parseInt("hello"); // NumberFormatException
```

Whitespace is not automatically trimmed:

``` java
int n = Integer.parseInt(" 123 ".trim());
```

### `valueOf(String s)`

Parses a decimal string and returns an `Integer`.

``` java
Integer n = Integer.valueOf("123");
```

Use this when an `Integer` object is needed. It may return a cached
instance.

### `parseInt(String s, int radix)`

Parses a string using the specified number base (radix). Valid radix
values are from 2 through 36.

``` java
int binary = Integer.parseInt("1010", 2); // 10
int octal  = Integer.parseInt("17", 8);   // 15
int hex    = Integer.parseInt("FF", 16);  // 255
```

The radix describes the base of the **input text**.

### `valueOf(String s, int radix)`

Like the radix version of `parseInt`, but returns `Integer`.

``` java
Integer n = Integer.valueOf("FF", 16); // 255
```

### `decode(String nm)`

Parses common integer string prefixes:

``` java
Integer.decode("123");  // decimal 123
Integer.decode("077");  // octal 63
Integer.decode("0xFF"); // hexadecimal 255
Integer.decode("#FF");  // hexadecimal 255
Integer.decode("-0x10");// decimal -16
```

`decode()` recognizes decimal, octal, and hexadecimal notation; it is
not a general replacement for `parseInt(s, radix)`. Invalid input causes
`NumberFormatException`.

## 7. Converting an `Integer` to other representations

### `intValue()`

Returns the represented primitive `int`.

``` java
Integer x = 42;
int n = x.intValue();
```

### `toString()`

Instance method that returns the decimal text of the value.

``` java
Integer x = 42;
String s = x.toString(); // "42"
```

### `Integer.toString(int i)`

Static method returning the decimal text of an `int`.

``` java
String s = Integer.toString(42);
```

### `Integer.toString(int i, int radix)`

Converts an integer to text in the specified base.

``` java
Integer.toString(10, 2);  // "1010"
Integer.toString(255, 16);// "ff"
Integer.toString(15, 8);  // "17"
```

The output uses letters such as `a`--`z` for digits above 9, usually in
lowercase.

### `toHexString(int i)`, `toOctalString(int i)`, `toBinaryString(int i)`

Convert the 32-bit `int` representation to hexadecimal, octal, or binary
text.

``` java
Integer.toBinaryString(10); // "1010"
Integer.toOctalString(10);  // "12"
Integer.toHexString(255);   // "ff"
```

For negative inputs, these methods show the two's-complement bit
representation, not a minus sign followed by the magnitude. For example:

``` java
Integer.toHexString(-1); // "ffffffff"
```

### `getInteger(String nm)` overloads

These methods read a **system property** and interpret its value as an
integer. They do not parse an arbitrary string argument directly.

``` java
System.setProperty("app.limit", "25");
Integer limit = Integer.getInteger("app.limit"); // 25
```

Overloads allow a default `int` or `Integer` to be supplied if the
property is missing or invalid. These methods are less commonly needed
in everyday application code.

## 8. Comparison and equality

### `compare(int x, int y)`

Compares two primitive integers.

``` java
Integer.compare(5, 10); // negative value
Integer.compare(10, 5); // positive value
Integer.compare(5, 5);  // 0
```

Only the sign matters: negative means the first value is smaller, zero
means equal, positive means larger. It avoids the overflow risk of
implementing comparison as `x - y`.

### `compareTo(Integer anotherInteger)`

Instance method from `Comparable<Integer>`.

``` java
Integer a = 10;
Integer b = 20;
int result = a.compareTo(b); // negative
```

Do not call it on a `null` reference.

### `equals(Object obj)`

Checks whether the other object is an `Integer` with the same numeric
value.

``` java
Integer a = 100;
Integer b = 100;
System.out.println(a.equals(b)); // true
```

### `==` versus `equals()`

For `Integer` references, `==` checks whether two references refer to
the same object; `equals()` checks represented values.

``` java
Integer a = 1000;
Integer b = 1000;

System.out.println(a.equals(b)); // true
System.out.println(a == b);      // Do not rely on this being true
```

Java caches certain boxed integer values, at least `-128` through `127`.
Therefore, some `Integer` values created by boxing or `valueOf()` may
share the same object. Cache behavior makes `==` unreliable for numeric
equality. Use `equals()` for object-value equality, or unbox and compare
primitive values when appropriate.

### `min(int a, int b)` and `max(int a, int b)`

Return the smaller or larger primitive value.

``` java
Integer.min(5, 9); // 5
Integer.max(5, 9); // 9
```

### `sum(int a, int b)`

Returns the sum of two `int` values.

``` java
Integer.sum(10, 20); // 30
```

This uses normal `int` arithmetic, so overflow is possible.

## 9. Arithmetic and overflow

`Integer` does not provide arbitrary-precision arithmetic. Its values
are still 32-bit `int` values.

``` java
int x = Integer.MAX_VALUE;
System.out.println(x + 1); // -2147483648 (overflow / wraparound)
```

Java integer overflow does not automatically throw an exception. If
overflow must be detected, use:

``` java
Math.addExact(10, 20);
Math.subtractExact(10, 20);
Math.multiplyExact(10, 20);
Math.incrementExact(10);
Math.decrementExact(10);
Math.negateExact(10);
```

These are methods of `Math`, not `Integer`; they throw
`ArithmeticException` if the exact result cannot fit in an `int`.

For calculations that may exceed the `int` range, consider `long`/`Long`
or `BigInteger`, depending on the required range.

## 10. Bit-manipulation methods

`Integer` provides static methods for working with the 32-bit binary
representation of an `int`. These are useful in bitwise programming,
algorithms, masks, flags, and low-level code.

### `bitCount(int i)`

Returns the number of set bits (`1` bits).

``` java
Integer.bitCount(10); // 2; binary 1010
```

For negative values, it counts set bits in the full 32-bit
two's-complement representation.

### `highestOneBit(int i)`

Returns a value with only the highest-order set bit retained.

``` java
Integer.highestOneBit(10); // 8; binary 1000
```

Returns `0` when the input is `0`.

### `lowestOneBit(int i)`

Returns a value with only the lowest-order set bit retained.

``` java
Integer.lowestOneBit(10); // 2; binary 0010
```

Returns `0` when the input is `0`.

### `numberOfLeadingZeros(int i)`

Counts zero bits before the highest-order `1` in the 32-bit
representation.

``` java
Integer.numberOfLeadingZeros(1);  // 31
Integer.numberOfLeadingZeros(8);  // 28
Integer.numberOfLeadingZeros(0);  // 32
```

### `numberOfTrailingZeros(int i)`

Counts zero bits after the lowest-order `1`.

``` java
Integer.numberOfTrailingZeros(8); // 3; binary ...1000
Integer.numberOfTrailingZeros(0); // 32
```

### `rotateLeft(int i, int distance)` and `rotateRight(int i, int distance)`

Rotate bits around the 32-bit boundary. Bits shifted out on one side
re-enter on the other side.

``` java
int x = 0b0001;
Integer.rotateLeft(x, 1);  // 0b0010
Integer.rotateRight(x, 1); // highest bit becomes set
```

Rotation is different from shifting: `<<` and `>>` discard bits that
leave the word, whereas rotation wraps them around. Rotation distance is
effectively reduced modulo 32.

### `reverse(int i)`

Reverses the order of all 32 bits.

``` java
int reversed = Integer.reverse(1);
```

The result is an `int`; printing it as a decimal number may not make the
bit pattern obvious. Use `Integer.toBinaryString(...)` when inspecting
it.

### `reverseBytes(int i)`

Reverses the order of the four bytes in the integer.

``` java
Integer.reverseBytes(0x12345678); // 0x78563412
```

Useful for byte-order transformations, but understand the surrounding
protocol and signedness before using it.

### `signum(int i)`

Returns `-1` for negative values, `0` for zero, and `1` for positive
values.

``` java
Integer.signum(-50); // -1
Integer.signum(0);   // 0
Integer.signum(50);  // 1
```

### `rotateLeft`, `rotateRight`, `reverse`, and signed values

These methods operate on the fixed-width 32-bit representation. They are
not ordinary arithmetic conversions. For bit-level tasks, inspect values
using `Integer.toBinaryString()` and remember that this method omits
leading zeros.

## 11. Unsigned integer operations

Java's `int` type is signed, but the `Integer` class offers methods to
interpret its bits as an unsigned 32-bit integer.

### `compareUnsigned(int x, int y)`

Compares two `int` bit patterns as unsigned values.

``` java
Integer.compareUnsigned(-1, 1); // positive
```

As an unsigned 32-bit value, `-1` has the bit pattern `0xFFFFFFFF`,
equivalent to `4,294,967,295`.

### `toUnsignedString(int i)`

Formats the bits as an unsigned decimal number.

``` java
Integer.toUnsignedString(-1); // "4294967295"
```

### `parseUnsignedInt(String s)` and `parseUnsignedInt(String s, int radix)`

Parse a non-negative textual value in the unsigned 32-bit range, from
`0` through `4,294,967,295`, and return its 32-bit bit pattern as an
`int`.

``` java
int bits = Integer.parseUnsignedInt("4294967295");
// bits has the same bit pattern as -1 when viewed as signed int
System.out.println(Integer.toUnsignedString(bits)); // "4294967295"
```

Values outside the unsigned 32-bit range or invalid text cause
`NumberFormatException`.

### `toUnsignedLong(int x)`

Widens the 32-bit pattern to a `long` while interpreting it as unsigned.

``` java
long value = Integer.toUnsignedLong(-1); // 4294967295L
```

### `divideUnsigned(int dividend, int divisor)` and `remainderUnsigned(int dividend, int divisor)`

Perform division and remainder using unsigned interpretation.

``` java
Integer.divideUnsigned(-1, 2);    // 2147483647
Integer.remainderUnsigned(-1, 2); // 1
```

The divisor must not be zero; division by zero throws
`ArithmeticException`.

## 12. `hashCode()` and `hashCode(int value)`

`hashCode()` returns the integer value as the hash code for an `Integer`
object.

``` java
Integer x = 123;
System.out.println(x.hashCode()); // 123
```

The static `Integer.hashCode(int value)` returns the hash code for a
primitive integer:

``` java
Integer.hashCode(123); // 123
```

This matters when `Integer` is used as a key in hash-based collections
such as `HashMap` and `HashSet`.

## 13. `describeConstable()` and `resolveConstantDesc(...)`

Modern Java versions include constant-description APIs inherited from
the `Constable` / `ConstantDesc` model. They are mainly relevant to JVM
tooling, bytecode generation, and constant descriptions; most beginners
do not need them in everyday application code. Their availability
depends on the Java version/API documentation being used.

## 14. Using `Integer` in collections and generics

Java generics cannot use primitive types as type arguments.

``` java
// List<int> values; // invalid
List<Integer> values = new ArrayList<>();
values.add(10); // autoboxing
int first = values.get(0); // unboxing
```

Example imports:

``` java
import java.util.ArrayList;
import java.util.List;

class Example {
    public static void main(String[] args) {
        List<Integer> numbers = new ArrayList<>();
        numbers.add(10);
        numbers.add(20);
        numbers.add(30);

        int total = 0;
        for (int number : numbers) {
            total += number;
        }

        System.out.println(total); // 60
    }
}
```

Watch for `null` elements: the enhanced `for` loop unboxes each
`Integer`, so a `null` element causes `NullPointerException`.

## 15. Sorting and `Integer`

`Integer` implements `Comparable<Integer>`, so collections of `Integer`
values can be sorted in natural ascending order.

``` java
List<Integer> numbers = new ArrayList<>(List.of(30, 5, 12));
numbers.sort(null);
System.out.println(numbers); // [5, 12, 30]
```

For primitive arrays, use `Arrays.sort(intArray)`. For object arrays,
`Arrays.sort(IntegerArray)` is also available.

Avoid comparison logic like `return a - b` in a comparator: subtraction
can overflow. Use `Integer.compare(a, b)`.

## 16. Common errors and misconceptions

1.  **Using `==` to compare two `Integer` objects.** Use `equals()` for
    value equality.
2.  **Unboxing `null`.** This throws `NullPointerException`.
3.  **Assuming overflow throws an exception.** Ordinary `int` arithmetic
    wraps around; use `Math.*Exact` methods when detection is required.
4.  **Confusing `parseInt()` and `valueOf()`.** `parseInt()` returns
    `int`; `valueOf()` returns `Integer`.
5.  **Confusing `decode()` with radix parsing.** `decode()` recognizes
    prefixes such as `0x`, `#`, and leading-zero octal notation.
6.  **Assuming `toBinaryString()` prints 32 digits.** It omits leading
    zeros for non-negative values.
7.  **Using `Integer` everywhere.** Primitive `int` is usually simpler
    and avoids nullable values and unnecessary boxing.
8.  **Assuming an `Integer` object can be changed.** It is immutable;
    operations produce primitive results or other values rather than
    mutating the object.
9.  **Assuming `Integer` can store arbitrarily large numbers.** Its
    underlying value is always a 32-bit signed integer; use `long` or
    `BigInteger` for larger ranges.

15. Parse `"4294967295"` as an unsigned integer and print it back using
    `toUnsignedString()`.

## 19. What to prioritize for exams and interviews

Prioritize these concepts first:

1.  `int` versus `Integer`; wrapper classes and immutability.
2.  Autoboxing and unboxing, including `NullPointerException`.
3.  `parseInt()`, `valueOf()`, `decode()`, and `toString()`.
4.  `MIN_VALUE`, `MAX_VALUE`, `SIZE`, and `BYTES`.
5.  `==` versus `equals()` and the integer cache.
6.  `compareTo()`, `compare()`, `min()`, `max()`, and `sum()`.
7.  Signed integer range and overflow.
8.  Bit methods and unsigned methods if your syllabus or interview
    preparation covers bit manipulation.

**Core takeaway:** `Integer` wraps a 32-bit signed `int` in an immutable
object. The most important practical issues are conversion,
boxing/unboxing, null handling, equality, overflow, and the specialized
bit/unsigned methods.
