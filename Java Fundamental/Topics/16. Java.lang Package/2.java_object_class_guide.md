# 👑 Deep Dive into the `Object` Class in Java


## 🌳 What is the `Object` Class?

In Java, the `Object` class is the **Ultimate Parent** (or root) of all classes. 

Imagine a massive family tree. At the very top of that tree is the `Object` class. Whether you create a class called `Car`, `Student`, or `BankAccount`, Java secretly and automatically makes it a "child" of the `Object` class.

### 🖼️ Visualizing the Class Hierarchy

```text
       [ java.lang.Object ]  <--- The Grandparent of EVERYTHING
                |
       -------------------
       |                 |
   [ String ]       [ Your Custom Class ]
                     (e.g., class Dog)
                         |
                   [ Puppy Class ]
```

**Why did Java do this?**
Because the creators of Java wanted *every single object* to share some basic, universal abilities. By putting these abilities in the `Object` class, every class automatically inherits them.

---

## 🛠️ The 9 Universal Methods of the `Object` Class

Since every class inherits from `Object`, every class automatically has these methods. Let's look at the most important ones:

1. **`toString()`**: Returns a text (String) representation of the object.
2. **`equals(Object obj)`**: Checks if two objects are meaningfully the exact same.
3. **`hashCode()`**: Returns a unique-looking integer (ID) for the object. *(We will deep-dive into this below!)*
4. **`getClass()`**: Tells you exactly what class the object belongs to at runtime.
5. **`clone()`**: Creates an exact copy of the object.
6. **`finalize()`**: Used right before an object is destroyed by the Garbage Collector (Note: Mostly outdated/deprecated now).
7. **`wait()`**, **`notify()`**, **`notifyAll()`**: These three are used for **Multithreading** (when multiple parts of a program run at the same time and need to talk to each other).

## 💻 Example: `toString()` and `equals()`

Let's see how we use (and change/override) these basic tools in a real class.

```java
class Student {
    int rollNumber;
    String name;

    Student(int rollNumber, String name) {
        this.rollNumber = rollNumber;
        this.name = name;
    }

    // 1. Overriding toString() so it prints nicely, instead of memory gibberish
    @Override
    public String toString() {
        return "Student Name: " + name + ", Roll No: " + rollNumber;
    }

    // 2. Overriding equals() so we can compare two students properly
    @Override
    public boolean equals(Object obj) {
        // If it's the exact same object in memory, return true
        if (this == obj) return true; 
        
        // If the other object is null or a different type, return false
        if (obj == null || this.getClass() != obj.getClass()) return false;
        
        // Compare the actual data (rollNumber and name)
        Student otherStudent = (Student) obj;
        return this.rollNumber == otherStudent.rollNumber && 
               this.name.equals(otherStudent.name);
    }
}

public class Main {
    public static void main(String[] args) {
        Student s1 = new Student(101, "Alice");
        Student s2 = new Student(101, "Alice");

        // Uses our custom toString()
        System.out.println(s1.toString()); 

        // Uses our custom equals() - Returns true because their data is the same!
        System.out.println("Are s1 and s2 equal? " + s1.equals(s2)); 
    }
}
```

## 🕵️‍♂️ Deep Dive: What is `hashCode()`?

This is one of the most common interview questions for beginners! 

### 1. The Analogy
Imagine a massive library with 1 million books. If you ask the librarian for "Harry Potter", searching every single shelf book-by-book would take forever.

Instead, the library has **sections** or **buckets** (e.g., Section 400 for Fantasy). The librarian calculates a "Code" based on the book's title, immediately walks to Section 400, and finds the book quickly.

In Java, **`hashCode()` is a mathematical formula that turns your object's data into a single Integer number (the bucket number).**

### 2. Where is it used?
Java uses `hashCode()` in ultra-fast data storage structures like **`HashMap`** and **`HashSet`**. When you save an object in a `HashMap`, Java looks at the `hashCode()` to decide which "bucket" to drop it in. When you want to find it later, Java calculates the `hashCode()` again and goes straight to that bucket!

### 🖼️ Visualizing HashCode and Buckets

```text
Object Data: "Alice", 101  ----(hashCode logic)----> Bucket #45
Object Data: "Bob", 102    ----(hashCode logic)----> Bucket #12
Object Data: "Charlie", 103 ---(hashCode logic)----> Bucket #89

Storage Bins (HashMap Memory):
[ Bucket 12 ] -> contains Bob
[ Bucket 45 ] -> contains Alice  <-- ultra fast lookup!
[ Bucket 89 ] -> contains Charlie
```

### 3. The Golden Contract 📜 (CRITICAL RULE)

Java has a strict rule (a contract) about `equals()` and `hashCode()`:

* **Rule 1:** If two objects are equal (meaning `equals()` returns true), they **MUST** have the exact same `hashCode()`.
* **Rule 2:** If two objects have the same `hashCode()`, they do *not* have to be equal. (This is called a "Hash Collision" — two different books can be put into the same library bucket).

Because of Rule 1, **if you override `equals()`, you MUST override `hashCode()` too!**

### 4. Code Example: Writing a good `hashCode()`

```java
import java.util.Objects;

class Employee {
    int id;
    String name;

    Employee(int id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (obj == null || getClass() != obj.getClass()) return false;
        Employee employee = (Employee) obj;
        return id == employee.id && name.equals(employee.name);
    }

    // Overriding hashCode to match equals!
    @Override
    public int hashCode() {
        // Java provides a handy utility to generate a good hash code based on your fields
        return Objects.hash(id, name);
    }
}
```

## 🎓 Summary

1. The **`Object` class** is the root of all Java classes.
2. It gives every object standard tools like `toString()` (for printing) and `equals()` (for comparing).
3. **`hashCode()`** gives your object an integer ID. This ID acts like a "bucket number" to help Java find your object lightning-fast in collections like `HashMap`.
4. **Never forget:** If you change how `equals()` works, you must also change how `hashCode()` works to keep the Golden Contract!
