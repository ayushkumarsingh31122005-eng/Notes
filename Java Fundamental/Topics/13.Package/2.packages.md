# 📦 The Ultimate Masterclass on Java Packages



## 1. The Two Types of Packages

In Java, packages are divided into two main categories:

1. **User-Defined Packages:** The ones you create yourself (like `com.mybank.accounts`).
2. **Built-in Packages (Java API):** The ones that come free with Java. The creators of Java wrote thousands of helpful classes and packaged them up for you.

### 🛠️ Important Built-in Packages You Must Know:
*   `java.lang`: Contains core classes like `String`, `Math`, and `System`.
*   `java.util`: Contains utility classes like `Scanner` (for user input), `ArrayList`, and `Date`.
*   `java.io`: Used for Input/Output (reading and writing files).
*   `java.net`: Used for networking (connecting to the internet).

---

## 2. The `import` Keyword: Bringing Code to Your File

If you are working inside the `com.school` package, and you want to use a `Scanner` from the `java.util` package, Java won't know where to find it. You have to "invite" it using the `import` keyword.

There are three ways to do this:

### Way A: Import a Single Class (Recommended)
This is the best practice in top companies because it is clear exactly what you are using.
```java
package com.school;

import java.util.Scanner; // We bring in ONLY the Scanner class

public class Student {
    Scanner input = new Scanner(System.in);
}
```

### Way B: Import the Entire Package (Using `*`)
The `*` (asterisk) means "import ALL classes inside this package".
```java
package com.school;

import java.util.*; // Brings in Scanner, Date, ArrayList, everything in util!

public class Student {
    Scanner input = new Scanner(System.in);
}
```
*Note: This does NOT import sub-packages. `import java.*;` will not import `java.util.Scanner`.*

### Way C: Fully Qualified Class Name (No import needed)
If you don't want to use the `import` keyword at the top, you can write the full package name right in the code.
```java
package com.school;

public class Student {
    // Look! No import at the top!
    java.util.Scanner input = new java.util.Scanner(System.in); 
}
```

## 3. 🤫 The Secret Package: `java.lang`

Have you ever wondered why you can use `String` or `System.out.println` without ever importing them? 

**The Secret:** Java secretly adds `import java.lang.*;` to the very top of *every single Java file* you ever write. It is the only package that is imported by default!

## 4. Static Imports (Advanced but Simple!)

Sometimes, you use a specific method from another class over and over. For example, `Math.sqrt()` (square root). A **static import** allows you to drop the class name and just use the method name.

**Without Static Import:**
```java
import java.lang.Math;

public class Calculator {
    double result = Math.sqrt(25); // You must type "Math."
}
```

**With Static Import:**
```java
import static java.lang.Math.sqrt; // Notice the 'static' keyword

public class Calculator {
    double result = sqrt(25); // You just type "sqrt" directly!
}
```

## 5. Sub-Packages

A sub-package is a package inside another package. 
For example: `java.util.concurrent`
* `java` is the main package.
* `util` is a sub-package inside `java`.
* `concurrent` is a sub-package inside `util`.

**Crucial Rule:** Importing a parent package does *not* import its sub-packages!
```java
import java.util.*; // This gets classes in util.
// It DOES NOT get classes in java.util.concurrent! 
// You must import them separately.
```

## 6. Packages and Security (Access Modifiers)

This is the most important reason MNCs use packages. Packages work with **Access Modifiers** to protect your code.

Imagine you have two packages: `bank` and `store`.

| Modifier | Who can use this class/variable? |
| :--- | :--- |
| **`public`** | ANYONE! A class in `store` can use a `public` class in `bank`. |
| **`private`** | ONLY the exact class it was written in. Packages don't even matter here. |
| **`protected`** | Classes in the SAME package, **OR** classes in different packages if they are "Child" classes (Inheritance). |
| **Default** (No keyword) | **PACKAGE-PRIVATE.** Only classes inside the EXACT SAME package can use it. It is hidden from the outside world! |

**Example of Package-Private (Default):**
```java
package bank;

// Notice there is no "public" keyword here!
class Vault { 
    int money = 1000000;
}
```
If a class in the `store` package tries to import `bank.Vault`, Java will throw a huge error. The `Vault` is safely hidden inside the `bank` package!

## 7. Complete Project Visualization & Compilation

Let's look at a complete professional project structure.

### 📂 Directory Structure:
```text
C:\MyProject\
 ├── 📂 src (Where you write your code)
 │    └── 📂 com
 │         └── 📂 mycompany
 │              ├── 📄 Main.java
 │              └── 📄 Helper.java
 │
 └── 📂 bin (Where compiled files go)
```

### 💻 The Code:

**Helper.java**
```java
package com.mycompany;

public class Helper {
    public void sayHello() {
        System.out.println("Hello from the Helper package!");
    }
}
```

**Main.java**
```java
package com.mycompany;

public class Main {
    public static void main(String[] args) {
        Helper myHelper = new Helper(); // Same package, no import needed!
        myHelper.sayHello();
    }
}
```

### 🔨 How to Compile and Run Like a Pro

Professional developers keep their source code (`.java`) separate from their compiled byte code (`.class`).

Open your terminal in `C:\MyProject\`.

**1. Compile to a specific folder (`bin`):**
```bash
javac -d bin src/com/mycompany/*.java
```
*(This compiles ALL java files in that folder and puts the `.class` files neatly into the `bin` folder!)*

**2. Run the program from the `bin` folder:**
```bash
java -cp bin com.mycompany.Main
```
*(`-cp bin` tells Java: "Hey, my classpath (where my compiled packages live) is the 'bin' folder. Go run the Main class inside com.mycompany.")*
