# Java Access Modifiers:


## 🏠 The Real-World Analogy
Imagine your code is like a house, and your packages are different neighborhoods.
1. **`private`**: Your personal diary. Only **you** (the specific Class) can read it.
2. **`default` (no keyword)**: The TV in your living room. Anyone living in the **same house/neighborhood** (Same Package) can watch it.
3. **`protected`**: A family recipe. People in your neighborhood (Same Package) can use it, AND your children who move to a **different neighborhood** (Subclasses in different packages) can also use it.
4. **`public`**: A public park. **Anyone, anywhere** can visit it.

---

## 📊 The "Cheat Sheet" Diagram
Here is the most important table you will use as a Java developer to remember how modifiers work in the context of packages. 

*Read this from top (most accessible) to bottom (least accessible).*

| Access Modifier | Inside Same Class | Inside Same Package | Subclass in a Different Package | Non-Subclass in a Different Package |
| :--- | :---: | :---: | :---: | :---: |
| **`public`** | ✅ Yes | ✅ Yes | ✅ Yes | ✅ Yes |
| **`protected`** | ✅ Yes | ✅ Yes | ✅ Yes | ❌ No |
| **`default`** *(no keyword)*| ✅ Yes | ✅ Yes | ❌ No | ❌ No |
| **`private`** | ✅ Yes | ❌ No | ❌ No | ❌ No |

*(Note: A **Subclass** is a class that inherits from another class using the `extends` keyword).*

## 💻 Detailed Explanations and Code Examples

Let's look at a practical example divided into two different packages: `neighborhood1` and `neighborhood2`.

### 1. `private` (Top Secret)
The `private` modifier is the strictest. A private variable or method can **only** be accessed within the exact same class where it is created.

```java
package neighborhood1;

public class MyHouse {
    // Private variable: Only MyHouse knows this password
    private String wifiPassword = "secret123";

    public void showPassword() {
        // This is allowed because we are INSIDE the MyHouse class
        System.out.println(wifiPassword); 
    }
}

class Neighbor {
    public void tryToConnect() {
        MyHouse house = new MyHouse();
        // ERROR! The Neighbor class cannot see a private variable.
        // System.out.println(house.wifiPassword); 
    }
}
```

### 2. Default (Package-Private)
If you don't write *any* modifier keyword, Java gives it "default" access. This is also called **Package-Private** because anything inside the **same package** can access it, but outside packages cannot.

```java
package neighborhood1;

public class MyHouse {
    // No keyword used! This is 'default' access.
    String livingRoomTV = "Samsung 55 inch"; 
}

class Neighbor {
    public void comeOver() {
        MyHouse house = new MyHouse();
        // This WORKS because Neighbor is in the SAME package (neighborhood1)
        System.out.println("Watching " + house.livingRoomTV); 
    }
}
```

### 3. `protected` (Family & Neighborhood)
The `protected` modifier allows access to everything in the **same package**, PLUS it allows access to **child classes** (subclasses) even if they live in a completely different package.

```java
package neighborhood1;

public class MyHouse {
    // Protected variable
    protected String familyRecipe = "Grandma's Cookies";
}
```

Now, let's create a child who moved to a different neighborhood (Package 2):

```java
package neighborhood2; // DIFFERENT PACKAGE!

import neighborhood1.MyHouse;

// The 'extends' keyword makes this a child (subclass) of MyHouse
public class ChildHouse extends MyHouse {
    
    public void bake() {
        // This WORKS! Because it is a subclass, it can access protected data 
        // even from a different package.
        System.out.println("Baking " + familyRecipe); 
    }
}

class Stranger {
    public void tryToBake() {
        MyHouse house = new MyHouse();
        // ERROR! A stranger in a different package cannot see protected data.
        // System.out.println(house.familyRecipe);
    }
}
```

### 4. `public` (Open to the World)
The `public` modifier is the easiest. If something is public, any class in any package can access it, as long as they import it.

```java
package neighborhood1;

public class MyHouse {
    // Public variable
    public String frontYardAddress = "123 Main St";
}
```

```java
package neighborhood2; // DIFFERENT PACKAGE

import neighborhood1.MyHouse;

public class DeliveryDriver {
    public void deliverPackage() {
        MyHouse house = new MyHouse();
        // This WORKS perfectly! Anyone can see a public variable.
        System.out.println("Delivering to " + house.frontYardAddress);
    }
}
```

## 🧠 Summary 

When writing your Java code, follow these best practices:
1. **Always start with `private`.** Keep your variables hidden (this is called **Encapsulation**) unless you absolutely need another class to see them.
2. If you need other classes in the *same folder* to help out, leave it as **default**.
3. If you are building a parent-child relationship (Inheritance) across different folders, use **protected**.
4. Use **public** mostly for Methods that you want the rest of the program to trigger, or Constants (`public static final`).
