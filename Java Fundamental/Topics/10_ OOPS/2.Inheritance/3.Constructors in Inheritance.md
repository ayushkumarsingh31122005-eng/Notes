# 1. What is a Constructor? (Quick Refresher)
Before jumping into inheritance, let's remember what a constructor is:
* A **Constructor** is a special block of code inside a class that runs automatically when you create an object (using the `new` keyword).
* Its main job is to **initialize values** for the object.
* It has the **same name as the class** and **no return type** (not even `void`).

---

## 2. The Big Question: What Happens to Constructors in Inheritance?
When Class B inherits from Class A (meaning `B` is a child and `A` is a parent), **constructors are NOT inherited**. 

Instead, a very important rule applies:
> **Whenever you create an object of the child class, Java *always* executes the parent class constructor first, before executing the child class constructor.**

Why? Because a child object is built upon the foundation of the parent object. You cannot build the second floor of a house without building the ground floor first!

---

## 3. Visualizing the Execution Flow

Let's look at how Java handles constructor execution when you create a child object:

```
[ You write: Dog myDog = new Dog(); ]
                   │
                   ▼
       ┌───────────────────────┐
       │ Dog() Constructor     │ (Child Constructor starts)
       └───────────┬───────────┘
                   │
                   ▼ (Calls super() implicitly or explicitly)
       ┌───────────────────────┐
       │ Animal() Constructor  │ (Parent Constructor runs FIRST)
       └───────────┬───────────┘
                   │
                   ▼ (Finishes parent setup)
       ┌───────────────────────┐
       │ Dog() Constructor     │ (Finishes child setup)
       └───────────────────────┘
                   │
                   ▼
     [ Object successfully created! ]
```

---

## 4. Code Example: Default Constructors in Inheritance

Let's see this in action with a simple Java program.

```java
// Parent Class (Superclass)
class Animal {
    // Parent Constructor
    Animal() {
        System.out.println("1. Animal constructor called: Parent is ready!");
    }
}

// Child Class (Subclass)
class Dog extends Animal {
    // Child Constructor
    Dog() {
        // Java automatically inserts super(); here behind the scenes!
        System.out.println("2. Dog constructor called: Child is ready!");
    }
}

public class Main {
    public static void main(String[] args) {
        // Creating an object of the Child class
        Dog myDog = new Dog();
    }
}
```

### Output:
```text
1. Animal constructor called: Parent is ready!
2. Dog constructor called: Child is ready!
```

## 5. The Magic Keyword: `super()`

What is that `super()` thing we mentioned above? 
* `super()` is a special keyword in Java used to call the **parent class constructor**.
* If you do not write `super()` inside a child constructor, Java adds it automatically as the **very first line**.

### What if the parent constructor takes parameters?
If your parent class has a constructor that requires arguments, Java **cannot** guess what values to pass. In this case, you **must** use `super(...)` explicitly in the child constructor to pass those values.

Let's see an example:

```java
// Parent Class with a parameterized constructor
class Vehicle {
    String brand;

    // Parameterized Constructor
    Vehicle(String brandName) {
        this.brand = brandName;
        System.out.println("Vehicle constructor called. Brand: " + brand);
    }
}

// Child Class
class Car extends Vehicle {
    int seatingCapacity;

    // Child Constructor taking parameters for both parent and child
    Car(String brandName, int seats) {
        super(brandName); // MUST be the first line! Calls Vehicle(brandName)
        this.seatingCapacity = seats;
        System.out.println("Car constructor called. Seats: " + seatingCapacity);
    }
}

public class Main {
    public static void main(String[] args) {
        // Creating a Car object
        Car myCar = new Car("Toyota", 5);
    }
}
```

### Output:
```text
Vehicle constructor called. Brand: Toyota
Car constructor called. Seats: 5
```

---

## 6. Critical Rules to Remember (Best Practices)

1. **`super()` must be first:** If you write `super()` explicitly in a child constructor, it **must** be the very first statement inside that constructor. If you put anything before it, Java will throw a compilation error.
2. **Implicit vs Explicit:** 
   * If the parent class has a **no-argument constructor**, Java adds `super();` automatically.
   * If the parent class has **only parameterized constructors**, you **must** call `super(arguments)` manually in the child constructor.
3. **`this()` vs `super()`:** 
   * `this()` calls another constructor in the *same* class.
   * `super()` calls a constructor in the *parent* class.
   * Because both must be the first statement, **you cannot use `this()` and `super()` in the same constructor together.**

## 7. Related Topics to Explore Next
Now that you understand constructors in inheritance, you can explore these related concepts to deepen your knowledge:
* **Method Overriding:** How child classes can modify behaviors inherited from parent classes.
* **The `super` Keyword (Field & Method Access):** Using `super.variableName` or `super.methodName()` to access parent members that were hidden or overridden.
* **Constructor Chaining:** The process of calling one constructor from another using `this()` and `super()`.
