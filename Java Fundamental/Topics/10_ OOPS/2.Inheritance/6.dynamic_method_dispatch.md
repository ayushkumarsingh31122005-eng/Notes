# Dynamic Method Dispatch in Java

## 1. What is Dynamic Method Dispatch?

Imagine you have a **Universal TV Remote** (Parent). You can use this single remote to control a **Sony TV** (Child 1) or an **LG TV** (Child 2). 

When you press the "Power" button on the remote, how does the remote know which TV to turn on? It depends on *which TV you paired it with at that exact moment*.

In Java, **Dynamic Method Dispatch** is the process where Java figures out *which* overridden method to run while the program is actually running (**at runtime**), rather than when you write the code (**at compile-time**).

This is also known as **Runtime Polymorphism**.

## 2. The Magic Ingredient: "Upcasting"

To understand this, you must first understand a rule in Java:
**A Parent class reference variable can hold a Child class object.**

Let's look at a simple line of code:
`Animal myPet = new Dog();`

* `Animal` is the **Reference Type** (The Universal Remote).
* `myPet` is the name of the variable.
* `new Dog()` is the **Actual Object** in memory (The specific Sony TV).

This concept is called **Upcasting**. We are looking at a `Dog` through the lens of a generic `Animal`.

## 3. Code Example & Syntax

Let's look at how Dynamic Method Dispatch works in action using Shapes.

```java
// 1. The Parent Class
class Shape {
    public void draw() {
        System.out.println("Drawing a generic shape...");
    }
}

// 2. Child Class 1
class Circle extends Shape {
    @Override
    public void draw() {
        System.out.println("Drawing a round Circle 🔵");
    }
}

// 3. Child Class 2
class Rectangle extends Shape {
    @Override
    public void draw() {
        System.out.println("Drawing a Rectangle ▭");
    }
}

// 4. The Main Class
public class Main {
    public static void main(String[] args) {
        
        // UPCASTING: Parent reference pointing to a Parent object
        Shape myShape = new Shape();
        myShape.draw(); // Output: Drawing a generic shape...

        // UPCASTING: Parent reference pointing to a Child object (Circle)
        myShape = new Circle(); 
        myShape.draw(); // Output: Drawing a round Circle 🔵

        // UPCASTING: Parent reference pointing to another Child object (Rectangle)
        myShape = new Rectangle();
        myShape.draw(); // Output: Drawing a Rectangle ▭
    }
}
```

### Notice What Happened!
We used the exact same variable `myShape`. We called the exact same method `myShape.draw()`. But every time, the output was different! Java *dynamically dispatched* the method call to the correct object (Circle or Rectangle) at runtime.

## 4. Visualizing How Java Thinks

Here is a diagram of what happens inside Java's brain during Dynamic Method Dispatch:

```mermaid
flowchart TD
    A[Code: myShape.draw()] --> B{Java checks: What is the Reference Type?}
    B -->|It is Shape| C[Compiler checks: Does 'Shape' have a draw method?]
    C -->|Yes, Compile Success!| D{Program Runs (Runtime): What is the ACTUAL object in memory?}
    D -->|Object is Circle| E[Execute Circle's draw method]
    D -->|Object is Rectangle| F[Execute Rectangle's draw method]
```

1. **Compile-Time:** The Java compiler only looks at the left side of the equals sign (`Shape`). It says, "Okay, Shape has a draw method, so this code is safe."
2. **Run-Time:** The Java Virtual Machine (JVM) looks at the right side of the equals sign (`new Circle()`). It says, "Ah! In reality, this is a Circle. I will run the Circle's version of the code."

## 5. Why is this so useful? (The Real-World Benefit)

You might ask, *"Why not just write `Circle c = new Circle();`?"*

Dynamic Method Dispatch allows us to write **flexible, generic code**. Imagine you are building a drawing application, and you want to draw 1,000 different shapes on the screen. 

Without this concept, you would need separate lists for circles, rectangles, triangles, etc.
With this concept, you can put them all in ONE list!

```java
// We can group all child objects under one Parent array!
Shape[] myShapes = new Shape[3];
myShapes[0] = new Circle();
myShapes[1] = new Rectangle();
myShapes[2] = new Shape();

// We can use a simple loop to draw everything!
for(int i = 0; i < myShapes.length; i++) {
    // Java dynamically figures out which draw() to call for each item!
    myShapes[i].draw(); 
}
```

## 6. Important Rule to Remember

**Dynamic Method Dispatch ONLY works for overridden methods.** 
It does *not* work for variables (data members). If both Parent and Child have a variable with the same name, Java will look at the *Reference Type* (Parent), not the Object Type. Methods are dynamic; variables are not!

***

### Summary
Dynamic Method Dispatch is Java's way of waiting until the very last second (runtime) to decide which version of an overridden method to execute, based on the *actual object* created in memory. It is the core of Runtime Polymorphism!
