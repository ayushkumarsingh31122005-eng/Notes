# Properties and Their Types in Java


When you hear the word "property," you might think of real estate. But in object-oriented programming and Java, a **property** refers to the characteristic, attribute, or state that belongs to an object. 

Let's dive deep into what properties are, how they work, and their various types in simple English!

---

## 1. What is a Property in Java?

In Java, a **property** is essentially a characteristic or attribute of an object. For example, if you have a `Car` object, its properties might include `color`, `brand`, `speed`, and `price`. 

Technically, in standard Java architecture (such as JavaBeans), a property is defined by a combination of:
1. A **private instance variable** (holding the data).
2. **Public getter and setter methods** (allowing controlled access to that data).

## 2. Types of Properties in Java

Properties in Java can be categorized based on their **access permissions** and **mutability** (how they can be changed). Here are the primary types:

### A. Read-Write Properties
* **Definition:** Properties that have **both** a getter and a setter method. 
* **Behavior:** You can both read the current value and modify/update it after the object is created.
* **Example:** A user's `email` or `password` in a profile class.

### B. Read-Only Properties
* **Definition:** Properties that have **only a getter** method and *no* setter.
* **Behavior:** Once the object is created (usually initialized via a constructor), the value cannot be changed. This makes the property **immutable**.
* **Example:** An `accountCreationDate` or a unique `id` number. Once assigned, it should never change.

### C. Write-Only Properties
* **Definition:** Properties that have **only a setter** method and *no* getter.
* **Behavior:** Allows you to send data into the object (like setting a password or configuration token), but you cannot read it back directly for security reasons.
* **Example:** A `password` field where you can update the password, but reading the raw password text back is a security violation.

## 3. Complete Code Example

Let's write a practical Java program that demonstrates Read-Write, Read-Only, and Write-Only properties in a single class called `UserProfile`.

```java
class UserProfile {
    // 1. Read-Write Property variable
    private String username;

    // 2. Read-Only Property variable (Initialized via constructor, no setter)
    private final String userId;

    // 3. Write-Only Property variable (Only has a setter, no getter)
    private String password;

    // Constructor to set initial values
    public UserProfile(String userId, String username) {
        this.userId = userId;
        this.username = username;
    }

    // --- READ-WRITE METHODS FOR USERNAME ---
    public String getUsername() {
        return username;
    }

    public void setUsername(String username) {
        if (username != null && !username.trim().isEmpty()) {
            this.username = username;
        }
    }

    // --- READ-ONLY METHOD FOR USER ID (Only Getter) ---
    public String getUserId() {
        return userId;
    }

    // --- WRITE-ONLY METHOD FOR PASSWORD (Only Setter) ---
    public void setPassword(String password) {
        if (password != null && password.length() >= 6) {
            this.password = password;
            System.out.println("Password successfully updated securely!");
        } else {
            System.out.println("Error: Password must be at least 6 characters long.");
        }
    }
}

public class Main {
    public static void main(String[] args) {
        // Creating an object with a read-only userId and initial username
        UserProfile user = new UserProfile("ID-9988", "Ayush_Dev");

        // 1. Testing Read-Write Property
        System.out.println("Initial Username: " + user.getUsername());
        user.setUsername("Ayush_Senior_Dev"); // Updating value
        System.out.println("Updated Username: " + user.getUsername());

        // 2. Testing Read-Only Property
        System.out.println("User ID (Read-Only): " + user.getUserId());
        // user.userId = "ID-1234"; // COMPILE ERROR: Cannot modify final/private field directly, and no setter exists!

        // 3. Testing Write-Only Property
        user.setPassword("Secret123"); // Updates the password via setter
        // System.out.println(user.getPassword()); // COMPILE ERROR: No getter method exists to read the password!
    }
}
```

### Execution Output:
```text
Initial Username: Ayush_Dev
Updated Username: Ayush_Senior_Dev
User ID (Read-Only): ID-9988
Password successfully updated securely!
```

## 4. Summary Table of Property Types

| Property Type | Has Getter? | Has Setter? | Mutable? | Use Case |
| :--- | :--- | :--- | :--- | :--- |
| **Read-Write** | Yes | Yes | Yes | Standard attributes that change over time (e.g., age, status). |
| **Read-Only** | Yes | No | No | Fixed attributes established at creation (e.g., creation date, ID). |
| **Write-Only** | No | Yes | Yes (Internally) | Sensitive configuration or credentials (e.g., passwords, tokens). |

---

## 5. Key Takeaways

* **Properties** represent the state and characteristics of an object in Java.
* They are built using **private variables** combined with public **getters and setters**.
* Depending on your application logic, properties can be designed as **Read-Write**, **Read-Only**, or **Write-Only** to enforce robust security and data control.
