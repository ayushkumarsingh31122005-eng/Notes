# 1. Data Hiding in Java

Imagine you own a high-tech locker at a bank. You keep your valuable cash and gold inside that locker. 
* Can anyone passing by reach inside and take your money? **No!**
* How do you interact with the locker? You use a key, a PIN, or a manager's assistance. 

In Java, **Data Hiding** is an object-oriented principle where we **hide the internal data (variables) of a class** from direct outside access. Instead of letting outside code modify your data directly, you restrict access and provide controlled entry points (methods) to view or update that data.

### Why do we need Data Hiding?
1. **Security:** Prevents unauthorized or accidental modification of critical data.
2. **Control:** Allows you to validate data before saving it (e.g., ensuring an age cannot be negative).
3. **Maintainability:** You can change how internal variables are stored without breaking the rest of the program.

## 3. How to Achieve Data Hiding in Java

To implement data hiding in Java, we use two main ingredients:
1. **`private` Access Modifier:** We declare our class variables as `private` so they cannot be accessed outside their own class.
2. **Getter and Setter Methods:** We provide `public` methods to read (`get`) and write (`set`) the private data safely.

---

## 4. Complete Code Example

Let's look at a practical, real-world example of a bank account to see data hiding in action.

```java
// StudentBankAccount.java
class BankAccount {
    // 1. DATA HIDING: Making the balance private so nobody can modify it directly
    private double balance;

    // 2. SETTER METHOD: To safely set or update the balance with validation
    public void setBalance(double amount) {
        if (amount > 0) {
            this.balance = amount;
            System.out.println("Balance updated successfully!");
        } else {
            System.out.println("Error: Invalid amount! Balance cannot be negative.");
        }
    }

    // 3. GETTER METHOD: To safely read the private balance
    public double getBalance() {
        return balance;
    }
}

public class Main {
    public static void main(String[] args) {
        // Creating an object of BankAccount
        BankAccount myAccount = new BankAccount();

        // ATTEMPT 1: Trying to access private variable directly (Will cause a Compile Error!)
        // myAccount.balance = 10000.0; // Error: balance has private access in BankAccount

        // ATTEMPT 2: Using Setter method to update balance safely
        myAccount.setBalance(5000.0);

        // ATTEMPT 3: Trying to set an invalid negative balance
        myAccount.setBalance(-2000.0);

        // ATTEMPT 4: Using Getter method to view the balance safely
        System.out.println("Current Account Balance: $" + myAccount.getBalance());
    }
}
```

### Output of the Program:
```text
Balance updated successfully!
Error: Invalid amount! Balance cannot be negative.
Current Account Balance: $5000.0
^
```

## 5. Related Topic: Encapsulation

You cannot talk about Data Hiding without mentioning its close relative: **Encapsulation**. 

* **Data Hiding** is specifically about **restricting access** to data using keywords like `private`.
* **Encapsulation** is the broader mechanism of **wrapping the data (variables) and code acting on the data (methods) together** as a single unit (a class).

> **Golden Rule in Java:** *Encapsulation = Data Hiding + abstraction of behavior.* In practice, a fully encapsulated class in Java always uses Data Hiding.

### Structure of an Encapsulated Class (Java Bean style):
1. Declare instance variables as `private`.
2. Provide `public` getter and setter methods for each variable.

---

## 6. Key Takeaways & Summary

* **What it is:** Keeping class variables hidden from outside classes.
* **How to do it:** Use the `private` keyword on variables.
* **How to access it:** Use `public` getter (to read) and setter (to write) methods.
* **Top Benefit:** Protects your application from bad data and gives you total control over how data is handled.
