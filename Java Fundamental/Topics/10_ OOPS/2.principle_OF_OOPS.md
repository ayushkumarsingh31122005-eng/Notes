# 🏛️ The 4 Pillars of OOP

To truly use OOP, Java follows four main principles (often called the 4 pillars). Think of them as the rules of the game.

### 1. Encapsulation 💊 (Data Protection)

**What is it?** Wrapping data (variables) and code (methods) together into a single unit. More importantly, it hides the sensitive data from the outside world.
**Real-World Example:** Think of a medicine capsule. The medicine is safe inside the shell. You can only swallow the capsule; you can't touch the chemical powders directly.

**How we do it in Java:** We make variables `private` and provide `public` methods (Getters and Setters) to access them safely.

```java
class BankAccount {
    // PRIVATE: No one can access this directly from outside!
    private double balance = 1000.0;

    // PUBLIC: A safe way to view the balance (Getter)
    public double getBalance() {
        return balance;
    }

    // PUBLIC: A safe way to deposit money (Setter)
    public void deposit(double amount) {
        if (amount > 0) {
            balance = balance + amount;
            System.out.println("Deposited safely!");
        } else {
            System.out.println("Invalid amount!");
        }
    }
}
```

### 2. Inheritance 🧬 (Parent-Child Relationship)

**What is it?** When one class acquires the properties and behaviors of another class. It promotes code reusability.
**Real-World Example:** A child inherits traits from their parents (like eye color or hair color). In programming, an `Animal` class can give its traits to a `Dog` class.

**How we do it in Java:** Using the `extends` keyword.

```java
// Parent Class (Superclass)
class Animal {
    void eat() {
        System.out.println("This animal eats food.");
    }
}

// Child Class (Subclass) inherits from Animal
class Dog extends Animal {
    void bark() {
        System.out.println("The dog barks: Woof!");
    }
}

public class Main {
    public static void main(String[] args) {
        Dog myDog = new Dog();
        myDog.eat();  // Inherited from Animal! It saves us from writing it again.
        myDog.bark(); // Its own behavior
    }
}
```

### 3. Polymorphism 🎭 (Many Forms)

**What is it?** "Poly" means many, and "morph" means forms. It allows a single action to behave differently based on the object performing it.
**Real-World Example:** Think of the word "Draw". If I tell you to draw, you might draw a picture. If I tell a gunslinger to draw, they pull out a weapon. Same word, different action!

**How we do it in Java:** There are two types: Overloading (same method name, different parameters) and Overriding (child class changes the parent's method). Here is an example of *Overriding*:

```java
class Animal {
    void makeSound() {
        System.out.println("Some generic animal sound");
    }
}

class Cat extends Animal {
    // Overriding: changing how makeSound behaves for a Cat
    @Override
    void makeSound() {
        System.out.println("Meow! Meow!");
    }
}

class Cow extends Animal {
    @Override
    void makeSound() {
        System.out.println("Moo! Moo!");
    }
}

public class Main {
    public static void main(String[] args) {
        Animal myCat = new Cat();
        Animal myCow = new Cow();
        
        myCat.makeSound(); // Outputs: Meow! Meow!
        myCow.makeSound(); // Outputs: Moo! Moo!
    }
}
```

### 4. Abstraction 🌫️ (Hiding Complexity)

**What is it?** Showing only the essential features to the user and hiding the complex background details.
**Real-World Example:** Driving a car. You know that pressing the accelerator makes the car go faster, and pressing the brake stops it. You don't need to know how the engine injects fuel or how the brake pads squeeze the tires. 

**How we do it in Java:** Using `abstract` classes or `interfaces`.

```java
// Abstract class: A partial blueprint that cannot be turned into an object directly
abstract class Vehicle {
    // Abstract method: Has no body! The child MUST provide the code for this.
    abstract void startEngine();
    
    // Regular method
    void turnOnLights() {
        System.out.println("Lights are on.");
    }
}

class Motorcycle extends Vehicle {
    // We are forced to provide the complex details here
    @Override
    void startEngine() {
        System.out.println("Kickstarting the motorcycle engine... Vroom!");
    }
}

public class Main {
    public static void main(String[] args) {
        // Vehicle v = new Vehicle(); // ERROR! Cannot create object of abstract class.
        
        Vehicle myBike = new Motorcycle();
        myBike.startEngine(); // Outputs: Kickstarting the motorcycle engine... Vroom!
        myBike.turnOnLights();
    }
}
```
