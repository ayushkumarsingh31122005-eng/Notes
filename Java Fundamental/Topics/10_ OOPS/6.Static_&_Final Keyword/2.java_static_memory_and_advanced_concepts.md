# Java Memory and the `static` Keyword



## 1. Where are `static` members created in Memory?

When you run a Java program, the Java Virtual Machine (JVM) divides the memory into different sections. The three most important ones for us are:

1. **Stack Memory:** Where your method executions and local variables live.
2. **Heap Memory:** Where all your regular Objects (created using `new`) live. 
3. **Method Area (Metaspace):** Where class structures and **`static` variables/methods** live.

### The Answer:
Static variables and static methods are stored in a special part of the memory called the **Method Area** (In modern Java 8 and newer, this is specifically called **Metaspace**). 

Because they live in the Method Area (which is loaded when the class first loads), they are completely independent of the Heap Memory where objects live. This is why you don't need an object to use them!

### Visual Diagram: Java Memory Model

```text
+-------------------------------------------------------------+
|                     JVM MEMORY SPACE                        |
|                                                             |
|  +-----------------------+       +-----------------------+  |
|  |     METHOD AREA       |       |      HEAP MEMORY      |  |

|  | Class Definitions     |       | Object 1 (Student)    |  |
|  |                       |       | Object 2 (Student)    |  |

|  | local variables       |                                  |
|  +-----------------------+                                  |
+-------------------------------------------------------------+
```

## Visual 2: The Java Memory Model (Where does it live?)

When you run your program, the Java Virtual Machine (JVM) acts like a big warehouse with different rooms. `static` gets its very own special room so it doesn't have to wait for objects to be built!

### Memory Map:

```text
+========================================================================+
|                    THE JVM MEMORY WAREHOUSE                            |
|========================================================================|
|                                                                        |
|  🏢 ROOM 1: METASPACE (Method Area)                                    |
|  ---------------------------------                                     |
|  This room is built FIRST.                                             |
|  [ static int collegeCode = 101; ] <------.                            |
|  [ static void getCollegeInfo()  ]        |                            |
|                                           |                            |
|===========================================|============================|
|                                           |                            |
|  🏠 ROOM 2: HEAP MEMORY                   |  📦 ROOM 3: STACK MEMORY   |
|  -----------------------                  |  -----------------------   |
|  Objects are built here using "new".      |  Methods run here.         |
|                                           |                            |
|  [ Object: s1 ]                           |  [ main() method ]         |
|    - name = "John"                        |    - s1 (points to Heap)   |
|    - (looks up at Metaspace) >------------'    - s2 (points to Heap)   |
|                                           |                            |

|    - name = "Emma"                        |                            |

```

**Takeaway:** Because `static` things live in **Room 1**, you can use them without ever building objects in **Room 2**.


## 2. What else is left related to `static`?

To make you 100% complete on this topic, here are three final concepts related to `static` that are very popular in MNC technical interviews:

### A. Static Import (Saving time typing)
Normally, if you want to use a static variable from Java's built-in Math class, you have to type the class name every time, like `Math.PI` or `Math.sqrt()`.

If you use a **static import**, you can skip the class name!

**Code Example:**
```java
// Regular way:
// import java.lang.Math;

// Static Import way:
import static java.lang.Math.PI;
import static java.lang.Math.sqrt;

public class Main {
    public static void main(String[] args) {
        // We don't need to write Math.PI, just PI!
        System.out.println("Value of PI: " + PI); 
        System.out.println("Square root: " + sqrt(25)); 
    }
}
```

### B. Static Methods in Interfaces (Java 8 Feature)
Before Java 8, interfaces could only have abstract methods (methods without a body). From Java 8 onwards, you can put **static methods with a full body** directly inside an Interface.

This is used to provide helpful "utility" methods directly in the interface.

**Code Example:**
```java
interface Vehicle {
    // Regular interface method
    void start(); 

    // Static method inside an interface!
    static void showRules() {
        System.out.println("Never drink and drive.");
    }
}

public class Main {
    public static void main(String[] args) {
        // You call it directly using the Interface name!
        Vehicle.showRules(); 
    }
}
```

### C. Method Hiding (You CANNOT Overide Static Methods)
In Java, when a child class changes a method of a parent class, it's called **Overriding**. But here is the golden rule: **You cannot override a static method.**

If a child class creates a static method with the exact same name as the parent's static method, it does not override it. Instead, it **hides** it. This is called *Method Hiding*. 

**Code Example:**
```java
class Parent {
    static void display() {
        System.out.println("Parent's static method");
    }
}

class Child extends Parent {
    // This is NOT overriding. This is Method Hiding!
    static void display() {
        System.out.println("Child's static method");
    }
}

public class Main {
    public static void main(String[] args) {
        Parent.display(); // Prints: Parent's static method
        Child.display();  // Prints: Child's static method
    }
}
```
