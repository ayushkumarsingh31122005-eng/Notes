# How Interfaces Enable Runtime Polymorphism in Java

Polymorphism is one of the four foundational pillars of Object-Oriented Programming (OOP). While classes define *how* things work, **interfaces provide the ultimate mechanism for achieving flexible, runtime polymorphism** in Java.

---

## 1. What is Polymorphism?

The word **Polymorphism** comes from Greek:
* **Poly** = Many
* **Morph** = Forms

In Java, **Polymorphism** means the ability of a single reference variable to take on different forms and exhibit different behaviors depending on the actual object it points to at runtime.

```
                           JAVA POLYMORPHISM
                                  |
            +---------------------+---------------------+
            |                                           |
            v                                           v
  Compile-Time Polymorphism                   Runtime Polymorphism
   (Static Method Overloading)               (Dynamic Method Overriding)
    - Resolved by Compiler                    - Resolved by JVM at Runtime
    - Same class, different parameters        - Accomplished via INTERFACES & Subclasses
```

## 3. How the JVM Performs Dynamic Method Dispatch

When you write polymorphic code with interfaces, two stages take place: **Compile Time** and **Runtime**.

```
STEP 1: COMPILE TIME (Type Checking)
-----------------------------------
Compiler checks: "Does the Interface type 'NotificationSender' contain the method send()?"
                 --> YES: Code compiles successfully.

STEP 2: RUNTIME (Dynamic Dispatch)
-----------------------------------
JVM checks: "What is the ACTUAL object stored in heap memory right now?"
            --> If object is EmailNotification  ==> Execute Email version of send()
            --> If object is SMSNotification    ==> Execute SMS version of send()
```

### Visualizing Method Lookup at Runtime

```
   STACK MEMORY                               HEAP MEMORY
   
+----------------------+              +----------------------------------+
| NotificationSender   | ------------>| EmailNotification Object         |
| sender               |              | -------------------------------- |
+----------------------+              | send() -> prints "Sending Email" |
                                      +----------------------------------+
          |
          | (Re-assigned at runtime)
          v
+----------------------+              +----------------------------------+
| NotificationSender   | ------------>| SMSNotification Object           |
| sender               |              | -------------------------------- |
+----------------------+              | send() -> prints "Sending SMS"   |
                                      +----------------------------------+
```

## 4. Complete Code Example: Polymorphic Notification System

Let's build a notification system where we can send messages through different channels seamlessly.

### Step 1: Create the Interface

```java
// File: NotificationSender.java
public interface NotificationSender {
    // Abstract contract method
    void send(String message);
}
```

### Step 2: Implement Concrete Classes

```java
// File: EmailNotification.java
public class EmailNotification implements NotificationSender {
    private String emailAddress;

    public EmailNotification(String emailAddress) {
        this.emailAddress = emailAddress;
    }

    @Override
    public void send(String message) {
        System.out.println("[EMAIL to " + emailAddress + "]: " + message);
    }
}
```

```java
// File: SmsNotification.java
public class SmsNotification implements NotificationSender {
    private String phoneNumber;

    public SmsNotification(String phoneNumber) {
        this.phoneNumber = phoneNumber;
    }

    @Override
    public void send(String message) {
        System.out.println("[SMS to " + phoneNumber + "]: " + message);
    }
}
```

```java
// File: PushNotification.java
public class PushNotification implements NotificationSender {
    private String deviceToken;

    public PushNotification(String deviceToken) {
        this.deviceToken = deviceToken;
    }

    @Override
    public void send(String message) {
        System.out.println("[PUSH to device " + deviceToken + "]: " + message);
    }
}
```

## 5. 3 Key Ways Interfaces Enable Polymorphism

### Pattern A: Polymorphic Reference Assignment

A single interface variable can reference any implementing instance.

```java
public class Main {
    public static void main(String[] args) {
        // One interface reference variable
        NotificationSender sender;

        // Pointing to Email
        sender = new EmailNotification("user@example.com");
        sender.send("Your order has shipped!"); 

        // Pointing to SMS
        sender = new SmsNotification("+1-555-0199");
        sender.send("Your OTP is 4821");

        // Pointing to Push Notification
        sender = new PushNotification("DEV-TOKEN-9981");
        sender.send("You have a new follower!");
    }
}
```

### Pattern B: Polymorphic Method Arguments

Methods can accept the interface type as a parameter. This allows passing **any** implementation to the method without changing its code.

```java
public class AlertSystem {
    // This method works for ANY notification type (Email, SMS, Push, etc.)
    public static void dispatchSecurityAlert(NotificationSender sender, String alertDetails) {
        System.out.println("--- INITIATING SECURITY ALERT ---");
        sender.send("CRITICAL: " + alertDetails);
    }

    public static void main(String[] args) {
        NotificationSender email = new EmailNotification("admin@company.com");
        NotificationSender sms = new SmsNotification("+1-800-555-0100");

        // Same method handles both implementations polymorphically!
        dispatchSecurityAlert(email, "Unauthorized login detected.");
        dispatchSecurityAlert(sms, "Server temperature exceeded threshold.");
    }
}
```

### Pattern C: Polymorphic Collections

You can store different concrete objects inside a single collection typed with the Interface.

```java
import java.util.ArrayList;
import java.util.List;

public class BulkNotifier {
    public static void main(String[] args) {
        // Polymorphic List holding different implementations
        List<NotificationSender> channels = new ArrayList<>();

        channels.add(new EmailNotification("alice@work.com"));
        channels.add(new SmsNotification("+1-555-3344"));
        channels.add(new PushNotification("DEVICE-KEY-882"));

        String updateMessage = "System maintenance scheduled at 12:00 AM UTC";

        // Single loop triggers specific behavior for each object dynamically!
        for (NotificationSender channel : channels) {
            channel.send(updateMessage);
        }
    }
}
```

**Output:**
```text
[EMAIL to alice@work.com]: System maintenance scheduled at 12:00 AM UTC
[SMS to +1-555-3344]: System maintenance scheduled at 12:00 AM UTC
[PUSH to device DEVICE-KEY-882]: System maintenance scheduled at 12:00 AM UTC
```

## 6. How Polymorphism via Interfaces Supports Design Principles

### 1. The Open/Closed Principle (SOLID)
* **Open for Extension:** You can create new implementations (e.g., `WhatsAppNotification`) by implementing `NotificationSender`.
* **Closed for Modification:** Existing notification dispatch code, batch processors, and main classes **never need to be touched or retested**.

```
                          NEW REQUIREMENT
                          WhatsApp Support
                                 |
                                 v
               +-----------------------------------+
               |  class WhatsAppNotification       |
               |  implements NotificationSender {  |
               |     ...                           |
               |  }                                |
               +-----------------------------------+
                                 |
           +---------------------+---------------------+
           |                                           |
           v                                           v
 EXISTING ALERT SYSTEM                      EXISTING BULK NOTIFIER
 (Needs 0 Code Changes!)                    (Needs 0 Code Changes!)
```

### 2. Dependency Inversion
Higher-level business modules depend on abstract interfaces rather than concrete low-level implementations.

## 7. Summary Cheat Sheet

| Feature | Details |
| :--- | :--- |
| **Interface Reference** | Holds references to any object implementing that interface (`Interface obj = new ConcreteClass()`). |
| **Method Execution** | Determined at **runtime** by the actual instance in memory (Dynamic Dispatch). |
| **Main Advantage** | Extensibility, loose coupling, plug-and-play architecture. |
| **Limitation** | The interface reference can only directly call methods declared in the interface. |
