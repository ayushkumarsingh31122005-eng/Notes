# Java Interfaces:



In simple terms, an **Interface** in Java is a **contract** or a **blueprint** for a class. It tells a class **WHAT to do**, but it does **NOT tell it HOW to do it**.

---

## 1. Real-World Analogy: The Universal Remote Control

Imagine you buy a universal TV remote control. 

* The remote has standard buttons: `powerOn()`, `powerOff()`, `volumeUp()`, and `volumeDown()`.
* This button layout is the **Interface**. It promises: *"If you press this button, the TV will turn on."*
* It doesn't matter whether you connect the remote to a **Sony TV**, a **Samsung TV**, or an **LG TV**. 
* Each TV brand executes `powerOn()` in its own internal way, but they all follow the **same button standard**.

```
                +----------------------------+
                |   << Interface >>          |
                |   UniversalRemote          |
                +----------------------------+
                | + powerOn()                |
                | + powerOff()               |
                +----------------------------+
                              |
        +---------------------+---------------------+
        |                     |                     |
  (implements)          (implements)          (implements)
        v                     v                     v
+---------------+     +---------------+     +---------------+
|    SonyTV     |     |   SamsungTV   |     |     LGTV      |
+---------------+     +---------------+     +---------------+
| powerOn() {   |     | powerOn() {   |     | powerOn() {   |
|  // Sony way  |     |  //Samsung way|     |  // LG way    |
| }             |     | }             |     | }             |
+---------------+     +---------------+     +---------------+
```

## 2. Why Do We Need Interfaces?

1. **Abstraction (Hiding Complexity):** The caller only cares about what methods exist, not how they work internally.
2. **Standardization / Loose Coupling:** Different parts of a system can interact without being tightly bound to specific implementations.
3. **Multiple Inheritance:** Java does not allow a class to inherit from multiple classes, but a class **can implement multiple interfaces**.

---

## 3. Basic Syntax and Keywords

Two primary keywords are used:
* **`interface`**: Declares the interface.
* **`implements`**: Used by a class to fulfill the interface contract.

```java
// Interface definition
public interface RemoteControl {
    // Abstract method (No body: no '{ }', ends with a semicolon ';')
    void powerOn();
    void powerOff();
}
```

### Important Rule for Beginners:
In an interface, methods without a body are automatically `public` and `abstract`. 
* Writing `void powerOn();` is identical to writing `public abstract void powerOn();`.

## 4. Full Working Code Example

Let's build a real-world payment system using an interface.

### Step 1: Define the Interface
```java
// File: PaymentProcessor.java
public interface PaymentProcessor {
    // Contract method: Every payment method must pay an amount
    void pay(double amount);
}
```

### Step 2: Implement the Interface in Different Classes
```java
// File: CreditCardPayment.java
public class CreditCardPayment implements PaymentProcessor {
    private String cardNumber;

    public CreditCardPayment(String cardNumber) {
        this.cardNumber = cardNumber;
    }

    @Override
    public void pay(double amount) {
        System.out.println("Paid $" + amount + " using Credit Card ending in " + cardNumber.substring(cardNumber.length() - 4));
    }
}
```

```java
// File: PayPalPayment.java
public class PayPalPayment implements PaymentProcessor {
    private String email;

    public PayPalPayment(String email) {
        this.email = email;
    }

    @Override
    public void pay(double amount) {
        System.out.println("Paid $" + amount + " using PayPal account: " + email);
    }
}
```

### Step 3: Run the Code (Polymorphism in Action)
```java
// File: ShoppingCart.java
public class ShoppingCart {
    public static void main(String[] args) {
        // We use the Interface type as the reference
        PaymentProcessor payment1 = new CreditCardPayment("1234-5678-9012-3456");
        PaymentProcessor payment2 = new PayPalPayment("user@example.com");

        // Both use the same method call 'pay', but execute different code!
        payment1.pay(150.00); // Output: Paid $150.0 using Credit Card ending in 3456
        payment2.pay(85.50);  // Output: Paid $85.5 using PayPal account: user@example.com
    }
}
```

## 5. Key Rules of Java Interfaces

### Rule 1: Cannot Be Instantiated
You **cannot** create an object of an interface directly using `new`:
```java
// ❌ COMPILE ERROR!
PaymentProcessor p = new PaymentProcessor(); 
```

### Rule 2: Variables are Constants (`public static final`)
Any variable declared inside an interface is automatically a constant.
```java
public interface AppConstants {
    // Automatically: public static final double TAX_RATE = 0.18;
    double TAX_RATE = 0.18; 
}
```

### Rule 3: Multiple Inheritance via Interfaces
A class can implement **as many interfaces as needed**, separated by commas:

```
+---------------+     +---------------+
|  <<Interface>>|     |  <<Interface>>|
|   Flyable     |     |   Swimmable   |
+---------------+     +---------------+
| + fly()       |     | + swim()      |
+---------------+     +---------------+
        ^                     ^
        |                     |
        +----------+----------+
                   |
            +--------------+
            |     Duck     |
            +--------------+
```

```java
public interface Flyable {
    void fly();
}

public interface Swimmable {
    void swim();
}

// Duck implements BOTH Flyable and Swimmable
public class Duck implements Flyable, Swimmable {
    @Override
    public void fly() {
        System.out.println("Duck is flying in the sky!");
    }

    @Override
    public void swim() {
        System.out.println("Duck is swimming in the pond!");
    }
}
```

## 6. Related Topics & Modern Features

### A. Interface vs. Abstract Class

| Feature | Interface | Abstract Class |
| :--- | :--- | :--- |
| **Multiple Inheritance** | A class can implement **multiple** interfaces. | A class can extend only **one** class. |
| **Variables** | Only `public static final` (constants). | Can have regular fields (`private`, `protected`, instance variables). |
| **Constructors** | **No** constructors allowed. | **Can** have constructors. |
| **Purpose** | Defines a **capability** or **contract** ("Can Do"). | Defines an **identity** or **base class** ("Is A"). |

---

### B. Modern Interface Features (Java 8 & Java 9)

Over time, Java introduced features to make interfaces more flexible without breaking existing code.

#### 1. `default` Methods (Java 8+)
Allows adding a method with a default implementation inside an interface.
```java
public interface Vehicle {
    void start();

    // Default method provides a default body!
    default void playRadio() {
        System.out.println("Playing music on default radio frequency FM 100.");
    }
}
```

#### 2. `static` Methods (Java 8+)
Utility methods that belong to the interface itself and do not require an object to run.
```java
public interface Vehicle {
    static boolean isElectric(String engineType) {
        return "ELECTRIC".equalsIgnoreCase(engineType);
    }
}

// Usage:
boolean check = Vehicle.isElectric("ELECTRIC"); // Returns true
```

#### 3. Functional Interfaces & Lambda Expressions (Java 8+)
An interface with **exactly ONE abstract method** is called a **Functional Interface**. It can be written compactly using **Lambda Expressions**:

```java
@FunctionalInterface
public interface MathOperation {
    int operate(int a, int b);
}

public class LambdaExample {
    public static void main(String[] args) {
        // Using a Lambda expression instead of creating a full class
        MathOperation addition = (a, b) -> a + b;
        System.out.println("Sum: " + addition.operate(10, 20)); // Output: Sum: 30
    }
}
```

## 7. Quick Summary Checklist

1. An interface defines **what** methods a class must implement.
2. Use the `interface` keyword to create it, and `implements` to use it in a class.
3. Interfaces allow Java classes to achieve **multiple inheritance**.
4. All methods without bodies are `public abstract` by default.
5. All fields are `public static final` constants by default.
6. Since Java 8, interfaces can have `default` and `static` methods with code bodies.
