## Use Case 1: Standardizing Framework APIs (The Contract Pattern)

The Java language creators use interfaces extensively to set standards that all developers must follow. 

### Real-World Analogy: USB Type-C Standard
Every phone manufacturer (Samsung, Google, Apple) uses the exact same USB Type-C plug interface. Because of this interface, charger makers don't need to create a unique charger for every single phone brand.

### Java Example: The Java Collections Framework
In Java, `List` is an interface. `ArrayList` and `LinkedList` are two different underlying data structures that both implement `List`.

```
                    +-----------------------+
                    |    << Interface >>    |
                    |         List          |
                    +-----------------------+
                    | + add(element)        |
                    | + remove(index)       |
                    | + get(index)          |
                    +-----------------------+
                                ^
                                |
             +------------------+------------------+
             |                                     |
+---------------------------+       +---------------------------+
|        ArrayList          |       |        LinkedList         |
| (Uses dynamic array behind|       | (Uses doubly-linked list  |
|  the scenes)              |       |  behind the scenes)       |
+---------------------------+       +---------------------------+
```

### Code Demonstration

```java
import java.util.ArrayList;
import java.util.LinkedList;
import java.util.List;

public class CollectionStandardDemo {

    // This method accepts ANY List implementation!
    public static void printElements(List<String> items) {
        for (String item : items) {
            System.out.println("Item: " + item);
        }
    }

    public static void main(String[] args) {
        // Switching implementations requires changing only one line!
        List<String> arrayList = new ArrayList<>();
        arrayList.add("Java");
        arrayList.add("Python");

        List<String> linkedList = new LinkedList<>();
        linkedList.add("C++");
        linkedList.add("Go");

        // The method works seamlessly for both types
        printElements(arrayList);
        printElements(linkedList);
    }
}
```

## Use Case 2: Plug-and-Play Architecture (Strategy Pattern)

Interfaces allow enterprise applications to swap out components (like payment engines, cloud storage providers, or notification channels) without rewriting the main software logic.

```
                          PLUG-AND-PLAY ARCHITECTURE
                          
                               +-------------------+
                               |  << Interface >>  |
                               |   CloudStorage    |
                               +-------------------+
                               | + uploadFile()    |
                               +-------------------+
                                         ^
                                         |
             +---------------------------+---------------------------+
             |                           |                           |
+--------------------------+ +--------------------------+ +--------------------------+
|     AWS S3 Storage       | |   Google Cloud Storage   | |    Azure Blob Storage    |
| (Implements uploadFile)  | | (Implements uploadFile)  | | (Implements uploadFile)  |
+--------------------------+ +--------------------------+ +--------------------------+
```

### Code Example: Swapping Cloud Providers

```java
// 1. The Interface Standard
public interface CloudStorage {
    void uploadFile(String fileName);
}

// 2. AWS Implementation
public class AwsStorage implements CloudStorage {
    @Override
    public void uploadFile(String fileName) {
        System.out.println("Uploading " + fileName + " to Amazon AWS S3 Bucket...");
    }
}

// 3. Google Cloud Implementation
public class GoogleCloudStorage implements CloudStorage {
    @Override
    public void uploadFile(String fileName) {
        System.out.println("Uploading " + fileName + " to Google Cloud Storage...");
    }
}

// 4. Main Application Service
public class DocumentService {
    private CloudStorage storage; // Program against Interface, not class!

    public DocumentService(CloudStorage storage) {
        this.storage = storage;
    }

    public void processDocument(String docName) {
        System.out.println("Document processed successfully.");
        storage.uploadFile(docName);
    }

    public static void main(String[] args) {
        // Today we use AWS
        DocumentService awsService = new DocumentService(new AwsStorage());
        awsService.processDocument("invoice_2026.pdf");

        // Tomorrow we can switch to Google Cloud without changing DocumentService code!
        DocumentService gcpService = new DocumentService(new GoogleCloudStorage());
        gcpService.processDocument("report_2026.pdf");
    }
}
```

## Use Case 3: Callbacks and Event Handling

Interfaces are heavily used in event-driven systems (like Web APIs, Mobile Apps, or UI Frameworks) to notify your code when a long-running task completes.

### Sequence Flow Diagram

```
[ Application Code ]                       [ Background Task Worker ]
         |                                             |
         | --- 1. Pass Callback Interface ------------> |
         |                                             | (Performs long computation...)
         |                                             | (Fetch data from network...)
         |                                             |
         | <--- 2. Call callback.onSuccess(data) ----- |
         v                                             v
```

### Code Example: Asynchronous Network Callback

```java
// 1. Define Callback Interface
public interface NetworkCallback {
    void onSuccess(String responseData);
    void onFailure(String errorMessage);
}

// 2. Background Worker
public class NetworkTask {
    public void fetchData(NetworkCallback callback) {
        System.out.println("Fetching data from server...");
        
        // Simulating network delay
        boolean isSuccess = true; 

        if (isSuccess) {
            callback.onSuccess("{ 'status': 200, 'message': 'Data loaded' }");
        } else {
            callback.onFailure("404 Not Found");
        }
    }
}

// 3. Application Execution
public class CallbackDemo {
    public static void main(String[] args) {
        NetworkTask task = new NetworkTask();

        // Pass an anonymous interface implementation as a listener/callback
        task.fetchData(new NetworkCallback() {
            @Override
            public void onSuccess(String responseData) {
                System.out.println("SUCCESS RECEIVED: " + responseData);
            }

            @Override
            public void onFailure(String errorMessage) {
                System.out.println("ERROR OCCURRED: " + errorMessage);
            }
        });
    }
}
```

## Use Case 4: Functional Interfaces & Modern Lambda Expressions

Starting in Java 8, interfaces with **exactly one abstract method** are called **Functional Interfaces**. They are the foundation for Lambda Expressions, enabling functional programming style in Java.

```
                  FUNCTIONAL INTERFACE TO LAMBDA TRANSFORMATION
                  
    Traditional Verbose Anonymous Class                Clean Modern Lambda Syntax
  +-------------------------------------+            +----------------------------+
  | Runnable r = new Runnable() {       |            |                            |
  |     public void run() {             |  =======>  | Runnable r = () ->         |
  |         System.out.println("Hi");   |            |     System.out.println("Hi");|
  |     }                               |            |                            |
  | };                                  |            +----------------------------+
  +-------------------------------------+
```

### Common Built-in Java Functional Interfaces

| Interface | Method Signature | Use Case |
| :--- | :--- | :--- |
| `Predicate<T>` | `boolean test(T t)` | Filtering data (Returns true/false) |
| `Function<T, R>` | `R apply(T t)` | Transforming data (Input type T $\rightarrow$ Output type R) |
| `Consumer<T>` | `void accept(T t)` | Consuming data (Takes input, returns nothing) |
| `Supplier<T>` | `T get()` | Generating data (Takes nothing, returns output) |

### Code Example: Stream API & Lambdas

```java
import java.util.Arrays;
import java.util.List;
import java.util.function.Predicate;

public class LambdaUseDemo {
    public static void main(String[] args) {
        List<Integer> numbers = Arrays.asList(10, 15, 20, 25, 30, 35);

        // Using Predicate Functional Interface with Lambda to filter even numbers
        Predicate<Integer> isEven = number -> number % 2 == 0;

        System.out.println("Even Numbers:");
        numbers.stream()
               .filter(isEven)
               .forEach(n -> System.out.println(n));
    }
}
```

## Use Case 5: Giving Multiple Behavioral Capabilities to a Class

In Java, a class can `extend` only **one** parent class, but it can `implement` **multiple** interfaces. Interfaces allow a single class to acquire multiple "abilities" or roles.

```
                            MULTIPLE CAPABILITIES
                            
     +-------------------+   +-------------------+   +-------------------+
     |  <<Interface>>    |   |  <<Interface>>    |   |  <<Interface>>    |
     |    Exportable     |   |    Printable      |   |    Encryptable    |
     +-------------------+   +-------------------+   +-------------------+
     | + exportToPdf()   |   | + printPaper()    |   | + encryptData()   |
     +-------------------+   +-------------------+   +-------------------+
               ^                       ^                       ^
               |                       |                       |
               +-----------------------+-----------------------+
                                       |
                         +---------------------------+
                         |      FinancialReport      |
                         |     (Implements All 3)    |
                         +---------------------------+
```

### Code Example

```java
public interface Exportable { void exportToPdf(); }
public interface Printable { void printPaper(); }
public interface Encryptable { void encryptData(); }

// A single class adopting 3 distinct capabilities
public class FinancialReport implements Exportable, Printable, Encryptable {

    @Override
    public void exportToPdf() { System.out.println("Exporting report to PDF..."); }

    @Override
    public void printPaper() { System.out.println("Sending report to physical printer..."); }

    @Override
    public void encryptData() { System.out.println("Encrypting report with AES-256..."); }
}
```

## Use Case 6: Marker Interfaces (Metadata Tagging)

A **Marker Interface** is an empty interface with **no methods and no fields**. 

### Why would an interface have no methods?
It serves as a "badge" or "tag" to tell the Java Virtual Machine (JVM) or a framework that a class has a special property.

```
                  MARKER INTERFACE PATTERN
                  
   +-----------------------+
   |    << Interface >>    |
   |      Serializable     |   <--- Empty! No methods inside.
   +-----------------------+
               ^
               | (Tagged with badge)
   +-----------------------+
   |      UserAccount      |   <--- Tells JVM: "This object is safe
   +-----------------------+        to convert into bytes & send over network"
```

### Examples of Standard Java Marker Interfaces
1. `java.io.Serializable`: Tells Java that objects of this class can be converted into a byte stream and saved to disk or sent over a network.
2. `java.lang.Cloneable`: Tells Java that the `clone()` method can safely make a field-for-field copy of instances of this class.
3. `java.util.RandomAccess`: Used by collections (like `ArrayList`) to signal that they support fast constant-time $O(1)$ random access.

### Code Example

```java
import java.io.Serializable;

// Tagging UserProfile with Serializable badge
public class UserProfile implements Serializable {
    // Serialization ID for version tracking
    private static final long serialVersionUID = 1L; 

    private String username;
    private String email;

    public UserProfile(String username, String email) {
        this.username = username;
        this.email = email;
    }
}
```

## Summary Matrix: Everyday Uses in Industry

| Use Case Pattern | Real-World Example | Primary Benefit |
| :--- | :--- | :--- |
| **API Standardization** | `List`, `Set`, `Map`, `Connection` (JDBC) | Ensures consistent method signatures across different library implementations. |
| **Plugin / Strategy Pattern** | Payment Gateways, Cloud Storage, Logging Drivers | Allows swapping low-level components with zero changes to main business logic. |
| **Event Callbacks** | `ActionListener`, `NetworkCallback` | Enables asynchronous task notification when processing finishes. |
| **Functional / Lambdas** | `Predicate`, `Consumer`, `Function`, `Runnable` | Enables clean, readable, functional code constructs in modern Java (Java 8+). |
| **Multiple Capabilities** | `Printable`, `Exportable`, `Cloneable` | Bypasses single inheritance limitation by attaching multiple behavioral capabilities. |
| **Marker Tagging** | `Serializable`, `RandomAccess` | Informs the JVM or third-party frameworks about class properties without code pollution. |

## Quick Review Checklist

1. **When to write an interface?** Write an interface whenever you foresee having multiple ways to perform an action (e.g., sending emails vs SMS, storing files on S3 vs local disk).
2. **Always Program to Interfaces:** Store instances using interface references (`List<String> list = new ArrayList<>()`) instead of concrete class references (`ArrayList<String> list = new ArrayList<>()`).
3. **Keep Interfaces Small:** Prefer small, focused interfaces with 1–3 methods rather than huge interfaces with 20 methods.
