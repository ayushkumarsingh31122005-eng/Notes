

# 36. Methods Can Call Other Methods

A method doesn't have to perform everything itself.

```java
static int square(int n) {
    return n * n;
}

static void printSquare(int n) {
    int result = square(n);
    System.out.println(result);
}
```

Then:

```java
printSquare(5);
```

Execution:

```text
main()
  ↓
printSquare(5)
  ↓
square(5)
  ↓
25
  ↓
print 25
```

This is one of the main ways larger programs are structured.

# 37. Methods and Arrays

Arrays can be passed to methods.

```java
static void printArray(int[] arr) {

    for (int i = 0; i < arr.length; i++) {
        System.out.println(arr[i]);
    }
}
```

Call:

```java
int[] numbers = {10, 20, 30};

printArray(numbers);
```

---

# 38. Methods Can Modify Mutable Objects

For example:

```java
static void update(int[] arr) {
    arr[0]++;
}
```

Calling:

```java
int[] numbers = {10, 20, 30};

update(numbers);
```

changes the array.

This is because the method receives a copy of the reference value pointing to the same array object.

# 39. Varargs Methods

Java supports variable-length arguments using `...`.

Example:

```java
static int sum(int... numbers) {

    int total = 0;

    for (int n : numbers) {
        total += n;
    }

    return total;
}
```

You can call:

```java
sum();
sum(10);
sum(10, 20);
sum(10, 20, 30, 40);
```

Inside the method, `numbers` behaves like an array.

For example:

```java
sum(10, 20, 30);
```

is conceptually treated as receiving an array containing those values.

Varargs are useful when the number of arguments can vary.

# 40. Access Modifiers on Methods

Methods can have different access levels.

### `public`

Accessible from wherever the declaring class is accessible, subject to Java's access rules.

```java
public void display() {
}
```

### `private`

Accessible only within the declaring class.

```java
private void calculate() {
}
```

### `protected`

Provides access according to Java's protected-access rules, including package access and specific subclass access.

```java
protected void display() {
}
```

### No modifier

This is called **package-private** access.

```java
void display() {
}
```

It is accessible within the same package, subject to the relevant type-access rules.

# 41. `final` Methods

A method can be declared `final`:

```java
final void display() {
}
```

A `final` instance method cannot be overridden by a subclass.

Example:

```java
class Parent {

    final void show() {
        System.out.println("Parent");
    }
}
```

A subclass cannot provide an overriding implementation of `show()`.

Oracle documents `final` methods as methods that cannot be overridden by subclasses.

---

# 42. `abstract` Methods

An abstract method does not provide an implementation in its declaration.

Example:

```java
abstract class Animal {

    abstract void sound();
}
```

There is no method body:

```java
abstract void sound();
```

A concrete subclass normally provides the implementation:

```java
class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Bark");
    }
}
```

Abstract methods are mainly associated with abstraction and inheritance.

---

# 43. `synchronized` Methods

A method can be declared:

```java
synchronized
```

Example:

```java
synchronized void update() {
    // critical section
}
```

This is related to **thread synchronization**.

For an instance synchronized method, the object's monitor is used for synchronization.

For a static synchronized method, the class's monitor is used.

This is an advanced topic and becomes important when learning multithreading.

# 44. Generic Methods

Java allows methods to define their own type parameters.

Example:

```java
static <T> void print(T value) {
    System.out.println(value);
}
```

Now:

```java
print(10);
print("Java");
print(10.5);
```

The method has its own type parameter:

```java
<T>
```

Generic methods are useful for writing reusable type-safe methods.

# 45. Method Execution and the Stack

When a method is invoked, the JVM creates an execution frame for the method.

Conceptually:

```text
Stack

┌─────────────────────┐
│ add() frame         │
│ a = 10              │
│ b = 20              │
│ sum = 30            │
└─────────────────────┘
          ↓
┌─────────────────────┐
│ main() frame        │
│ result = ...        │
└─────────────────────┘
```

When `add()` finishes, its execution frame is removed and control returns to the caller.

The JLS describes method invocation as involving evaluation of the target and arguments, locating the method, creating an execution frame, and transferring control.

# 46. Important: Method Declaration vs Method Call

Do not confuse these.

### Declaration

You define the method:

```java
static int add(int a, int b) {
    return a + b;
}
```

### Invocation

You execute the method:

```java
add(10, 20);
```

Think:

```text
Declaration = "What should this method do?"

Invocation = "Execute this method now."
```

# 47. Method vs Constructor

Beginners often confuse these.

### Method

A method represents behavior.

```java
void display() {
    System.out.println("Hello");
}
```

### Constructor

A constructor is used when creating and initializing an object.

```java
Student() {
    System.out.println("Object created");
}
```

Important differences:

| Method                                                | Constructor                        |
| ----------------------------------------------------- | ---------------------------------- |
| Has a return type or `void`                           | Has no return type                 |
| Can be invoked as a method                            | Invoked as part of object creation |
| Represents behavior                                   | Initializes an object              |
| Can be inherited/overridden according to method rules | Constructors are not inherited     |
| Name can be different from class name                 | Name must match class name         |

Constructors are similar to methods in some ways, but Java treats them as a distinct language construct.
