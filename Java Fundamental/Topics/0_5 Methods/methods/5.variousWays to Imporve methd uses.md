

# 48. Common Beginner Mistakes

## Mistake 1: Forgetting parentheses

Wrong:

```java
greet;
```

Correct:

```java
greet();
```

---

## Mistake 2: Returning the wrong type

Wrong:

```java
static int getNumber() {
    return "10";
}
```

Correct:

```java
static int getNumber() {
    return 10;
}
```

---

## Mistake 3: Forgetting `return`

Wrong:

```java
static int add(int a, int b) {
    int result = a + b;
}
```

The method promises to return an `int`, but doesn't return one.

Correct:

```java
static int add(int a, int b) {
    int result = a + b;
    return result;
}
```

---

## Mistake 4: Using a local variable outside its scope

Wrong:

```java
static void test() {
    int x = 10;
}

static void display() {
    System.out.println(x);
}
```

`x` exists only within `test()`.

---

## Mistake 5: Thinking Java passes primitives by reference

Wrong assumption:

```java
static void change(int x) {
    x = 100;
}
```

This does not change the caller's variable.

Java is always pass-by-value.

---

## Mistake 6: Thinking return type determines overloading

This is invalid:

```java
int test() { ... }

double test() { ... }
```

Return type alone cannot distinguish overloaded methods.

---

## Mistake 7: Calling an instance method without an object

Consider:

```java
class Test {

    void display() {
        System.out.println("Hello");
    }
}
```

From a static context such as `main`, you generally need an instance:

```java
Test obj = new Test();

obj.display();
```

# 49. Best Practices

### 1. Give methods meaningful names

Prefer:

```java
calculateAverage()
```

over:

```java
doSomething()
```

---

### 2. Keep methods focused

A method should ideally have one clear responsibility.

Instead of:

```java
processEverything()
```

prefer smaller methods such as:

```java
readInput()
calculateTotal()
validateInput()
printResult()
```

---

### 3. Avoid unnecessarily long methods

If a method becomes very large and performs many unrelated tasks, consider splitting it.

---

### 4. Use parameters instead of duplicated code

Instead of:

```java
static void print10() {
    System.out.println(10);
}

static void print20() {
    System.out.println(20);
}
```

prefer:

```java
static void printNumber(int n) {
    System.out.println(n);
}
```

---

### 5. Use return values when the caller needs the result

Instead of:

```java
static void add(int a, int b) {
    System.out.println(a + b);
}
```

if the result needs further processing, prefer:

```java
static int add(int a, int b) {
    return a + b;
}
```

Then:

```java
int result = add(10, 20);
```

---

# Complete Example

```java
public class Calculator {

    static int add(int a, int b) {
        return a + b;
    }

    static int subtract(int a, int b) {
        return a - b;
    }

    static int multiply(int a, int b) {
        return a * b;
    }

    static double divide(int a, int b) {
        return (double) a / b;
    }

    public static void main(String[] args) {

        int x = 20;
        int y = 10;

        int sum = add(x, y);
        int difference = subtract(x, y);
        int product = multiply(x, y);
        double quotient = divide(x, y);

        System.out.println("Sum = " + sum);
        System.out.println("Difference = " + difference);
        System.out.println("Product = " + product);
        System.out.println("Quotient = " + quotient);
    }
}
```

Output:

```text
Sum = 30
Difference = 10
Product = 200
Quotient = 2.0
```

The program is divided into multiple methods, with each method responsible for one operation.

This is much easier to maintain than putting all calculations directly inside `main()`.

# . Recommended Learning Order

If you are learning Java from the beginning, study methods in this order:

```text
Methods
  │
  ├── Method declaration
  │
  ├── Method invocation
  │
  ├── Parameters
  │
  ├── Arguments
  │
  ├── Return values
  │
  ├── void methods
  │
  ├── Local variables & scope
  │
  ├── Static methods
  │
  ├── Instance methods
  │
  ├── Passing primitives
  │
  ├── Passing arrays/objects
  │
  ├── Method overloading
  │
  ├── Varargs
  │
  ├── Recursion
  │
  └── Overriding + polymorphism
          ↓
     OOP concepts
```

Do **not** rush into overriding, generics, `synchronized`, or other advanced method features before you are comfortable with parameters, return values, scope, `static`, and pass-by-value.
