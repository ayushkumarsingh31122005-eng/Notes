# Master Java Exception Handling

 **Exception Handling** is your spare tire and toolkit. It prevents your car (program) from crashing and helps you recover gracefully.


---

## 1. Types of Errors in Java

Before we fix problems, we need to know what they are. In Java, problems are divided into three main categories:

1.  **Syntax Errors:** Mistakes in your code's grammar (e.g., missing a semicolon `;`). The compiler catches these, and your program won't even run.
2.  **Logical Errors:** Your program runs, but it gives the wrong output (e.g., adding `a + b` when you meant to multiply `a * b`).
3.  **Runtime Errors (Exceptions):** The code is grammatically correct, but something goes wrong *while* the program is running (e.g., trying to read a file that doesn't exist, or dividing a number by zero).

### The Throwable Hierarchy (Visual Diagram)

Here is how Java organizes these runtime issues under the hood:

```text
                     Throwable (Super class of all errors and exceptions)
                     /       \
                    /         \
                 Error      Exception
                 /             /     \
    (Out of memory,           /       \
     System crash)     Checked      Unchecked (Runtime)
    (Cannot be caught) (Compile time) (NullPointer, Arithmetic)
```

*   **Errors:** Severe issues like running out of memory. We usually don't try to fix these in code.
*   **Checked Exceptions:** Java *forces* you to handle these before running (e.g., `IOException`).
*   **Unchecked Exceptions:** Logic mistakes that happen at runtime (e.g., `ArithmeticException`).

## 2. Exception Handling & Ways to Fix

**Exception Handling** is a mechanism to handle runtime errors so that the normal flow of the application is maintained. 

The main tools (keywords) we use to fix/handle exceptions are:
*   `try`: To test a block of code for errors.
*   `catch`: To handle the error if it occurs.
*   `finally`: To execute code after try/catch, regardless of what happened.
*   `throw`: To manually create an exception.
*   `throws`: To declare that a method might cause an exception.

---

## 3. The `try` and `catch` Block

You place risky code inside a `try` block. If an error happens, the code jumps immediately to the `catch` block.

```java
public class BasicTryCatch {
    public static void main(String[] args) {
        System.out.println("Program started...");
        
        try {
            // Risky code
            int result = 10 / 0; // This causes an ArithmeticException
            System.out.println("This line will NOT print."); 
        } catch (ArithmeticException e) {
            // How we handle the error
            System.out.println("Error found: You cannot divide by zero!");
        }
        
        System.out.println("Program finished normally."); // This will print!
    }
}
```

---

## 4. Multiple Catch Blocks for One Try Block

Sometimes, a single `try` block might have code that can throw *different kinds* of exceptions. You can use multiple `catch` blocks to handle each specific problem differently.

```java
public class MultipleCatch {
    public static void main(String[] args) {
        try {
            int[] numbers = {1, 2, 3};
            System.out.println(numbers[5]); // Throws ArrayIndexOutOfBoundsException
            
            int result = 10 / 0; // Throws ArithmeticException (if it reached here)
            
        } catch (ArithmeticException e) {
            System.out.println("Math error occurred.");
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("Array index is wrong!");
        }
    }
}
```

---

## 5. Catch Block Ordering ("Catch block should not be super")

**CRITICAL RULE:** When using multiple catch blocks, you must order them from **most specific (child)** to **most general (parent/super)**. 

Because `Exception` is the parent class of all exceptions, if you put it at the top, it will catch *everything*, and the specific catch blocks below it will never run (Java will give you a compiler error saying the code is unreachable).

### ❌ WRONG WAY:
```java
try {
    int a = 10 / 0;
} catch (Exception e) { // SUPER CLASS is catching everything first!
    System.out.println("Some error happened.");
} catch (ArithmeticException e) { // COMPILE ERROR: Unreachable code
    System.out.println("Divide by zero.");
}
```

### ✅ CORRECT WAY:
```java
try {
    int a = 10 / 0;
} catch (ArithmeticException e) { // Specific child first
    System.out.println("Divide by zero.");
} catch (Exception e) { // Super class at the very bottom as a fallback
    System.out.println("Some other error happened.");
}
```

## 6. Nested Try and Catch Block

Sometimes, inside a `try` block, you need another `try` block. This is useful when different parts of a complex process need their own error handling.

```java
public class NestedTry {
    public static void main(String[] args) {
        try { // Outer try
            System.out.println("Outer try block starts.");
            
            try { // Inner try
                int result = 10 / 0; 
            } catch (ArithmeticException e) {
                System.out.println("Handled inner math error.");
            }
            
            // Outer try continues
            int[] arr = new int[2];
            arr[5] = 100; // Throws exception to outer catch
            
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("Handled outer array error.");
        }
    }
}
```

## 7. The `finally` Block & The Cleanup Process

The `finally` block is code that **always executes**, whether an exception happens or not. 

### What is the "Cleanup Process"?
When your program connects to a database, opens a file, or uses a network, it uses system resources. If your code crashes, those resources might stay open, causing memory leaks. The cleanup process involves closing those resources. The `finally` block is the perfect place for this!

```java
import java.util.Scanner;

public class FinallyExample {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        
        try {
            System.out.print("Enter a number: ");
            int num = Integer.parseInt(scanner.nextLine());
            System.out.println("You entered: " + num);
        } catch (NumberFormatException e) {
            System.out.println("That was not a valid number!");
        } finally {
            // CLEANUP PROCESS: This happens no matter what!
            System.out.println("Closing the scanner resource...");
            scanner.close(); 
        }
    }
}
```
**Why `finally` is powerful:** Even if you write a `return` statement inside the `try` or `catch` block, the `finally` block will still execute before the method actually returns!
