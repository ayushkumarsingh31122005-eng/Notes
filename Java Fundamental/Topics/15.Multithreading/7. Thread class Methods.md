# Comprehensive Deep-Dive: The `java.lang.Thread` Class API



## 1. Thread Constructors

Java's `Thread` class provides several constructors to initialize thread instances with different configurations, tasks, names, and thread groups.

### A. `Thread()`
* **Signature:** `public Thread()`
* **Description:** Creates a new `Thread` object with a default generated name (`Thread-0`, `Thread-1`, etc.), default priority, and no target `Runnable` task.
* **Internal Behavior:** When using this constructor, you typically override the `run()` method by extending the `Thread` class.
* **Code Example:**
  ```java
  Thread t = new Thread() {
      @Override
      public void run() {
          System.out.println("Executing inside default Thread constructor");
      }
  };
  t.start();
  ```

### B. `Thread(Runnable target)`
* **Signature:** `public Thread(Runnable target)`
* **Description:** Allocates a new `Thread` object that executes the `run()` method of the specified `Runnable` target.
* **Internal Behavior:** Decouples the thread execution mechanism from the task logic.
* **Code Example:**
  ```java
  Runnable task = () -> System.out.println("Running target task!");
  Thread t = new Thread(task);
  t.start();
  ```

### C. `Thread(Runnable target, String name)`
* **Signature:** `public Thread(Runnable target, String name)`
* **Description:** Creates a thread with a specified `Runnable` task and a custom human-readable name.
* **Use Case:** Custom thread names are vital for debugging and inspecting logs or thread dumps in production environments.
* **Code Example:**
  ```java
  Thread t = new Thread(() -> System.out.println("Processing payment..."), "Payment-Worker-1");
  t.start();
  ```

### D. `Thread(ThreadGroup group, String name)`
* **Signature:** `public Thread(ThreadGroup group, String name)`
* **Description:** Assigns the new thread to a specific `ThreadGroup` alongside setting its custom name.
* **Internal Behavior:** Inherits properties and access controls specified by the `ThreadGroup`.
* **Code Example:**
  ```java
  ThreadGroup poolGroup = new ThreadGroup("DatabasePool");
  Thread t = new Thread(poolGroup, "DB-Connection-Worker");
  System.out.println("Group Name: " + t.getThreadGroup().getName()); // Outputs: DatabasePool
  ```

### E. `Thread(String name)`
* **Signature:** `public Thread(String name)`
* **Description:** Allocates a new `Thread` object with a designated custom name without an initial `Runnable` target.
* **Use Case:** Used when subclassing `Thread` and giving the custom subclass thread a specific name during initialization.
* **Code Example:**
  ```java
  class CustomWorker extends Thread {
      public CustomWorker(String name) {
          super(name);
      }
      @Override
      public void run() {
          System.out.println("Subclass thread running with name: " + getName());
      }
  }
  CustomWorker worker = new CustomWorker("CustomWorkerThread");
  worker.start();
  ```

## 2. Getter & Setter Methods

These methods allow inspecting and modifying a thread's metadata and state properties.

### A. `long getId()` / `long threadId()`
* **Signature:** `public long getId()` *(Deprecated in Java 19 in favor of `threadId()`)*
* **Description:** Returns the unique positive `long` identifier assigned to the thread upon creation.
* **Key Characteristic:** The ID remains unchanged during the thread's lifetime. When the thread dies, its ID may be recycled.

### B. `String getName()`
* **Signature:** `public final String getName()`
* **Description:** Returns the current name of the thread.

### C. `int getPriority()`
* **Signature:** `public final int getPriority()`
* **Description:** Returns the execution priority of the thread (an integer between `1` and `10`).

### D. `Thread.State getState()`
* **Signature:** `public Thread.State getState()`
* **Description:** Returns the current execution state of the thread as an enum value (`NEW`, `RUNNABLE`, `BLOCKED`, `WAITING`, `TIMED_WAITING`, `TERMINATED`).

### E. `ThreadGroup getThreadGroup()`
* **Signature:** `public final ThreadGroup getThreadGroup()`
* **Description:** Returns the `ThreadGroup` to which this thread belongs, or `null` if the thread has died.

### F. `void setName(String name)`
* **Signature:** `public final void setName(String name)`
* **Description:** Changes the name of the thread.
* **Throws:** `SecurityException` if the current thread cannot modify this thread.

### G. `void setPriority(int newPriority)`
* **Signature:** `public final void setPriority(int newPriority)`
* **Description:** Sets the priority of the thread. Must be between `Thread.MIN_PRIORITY` (1) and `Thread.MAX_PRIORITY` (10).
* **Throws:** `IllegalArgumentException` if `newPriority` is outside `1..10`.

### H. `void setDaemon(boolean on)`
* **Signature:** `public final void setDaemon(boolean on)`
* **Description:** Marks the thread as either a daemon thread (`true`) or a user thread (`false`).
* **Critical Rule:** Must be called **before** invoking `start()`.
* **Throws:** `IllegalThreadStateException` if called while the thread is active.

```java
public class GetterSetterDemo {
    public static void main(String[] args) {
        Thread t = new Thread(() -> {}, "DataFetcher");
        
        t.setPriority(7);
        t.setDaemon(true);
        
        System.out.println("ID: " + t.getId());
        System.out.println("Name: " + t.getName());
        System.out.println("Priority: " + t.getPriority());
        System.out.println("State: " + t.getState());
        System.out.println("Daemon? " + t.isDaemon());
    }
}
```

## 3. Enquiry Methods

Enquiry methods query the current status or flags of a thread.

### A. `boolean isAlive()`
*(Note: Commonly referenced as `isActive` in context)*
* **Signature:** `public final boolean isAlive()`
* **Description:** Tests if this thread is alive. A thread is alive if it has been started and has not yet died (i.e., in `RUNNABLE`, `BLOCKED`, `WAITING`, or `TIMED_WAITING` state).

### B. `boolean isDaemon()`
* **Signature:** `public final boolean isDaemon()`
* **Description:** Returns `true` if the thread is a daemon thread, otherwise `false`.

### C. `boolean isInterrupted()`
* **Signature:** `public boolean isInterrupted()`
* **Description:** Tests whether this thread has been interrupted. 
* **Key Detail:** Unlike the static `Thread.interrupted()` method, this instance method **does not clear** the thread's interrupted flag status.

```java
Thread t = new Thread(() -> {
    try {
        Thread.sleep(5000);
    } catch (InterruptedException e) {
        System.out.println("Interrupted! Flag check inside catch: " + Thread.currentThread().isInterrupted());
    }
});

t.start();
System.out.println("Is alive before interrupt? " + t.isAlive());
t.interrupt();
```

## 4. Instance Methods

Instance methods control execution flow, lifecycle, and interruption mechanics of specific thread instances.

### A. `void interrupt()`
* **Signature:** `public void interrupt()`
* **Description:** Interrupts the target thread.
* **Behavior:**
  1. If the thread is blocked in `sleep()`, `wait()`, or `join()`, its interrupt status is cleared and it receives an `InterruptedException`.
  2. If the thread is running normally, its interrupt flag is set to `true`.

### B. `void join()`
* **Signature:** `public final void join() throws InterruptedException`
* **Description:** Suspends the execution of the calling thread until the target thread on which `join()` was called completes execution (`TERMINATED`).

### C. `void join(long millis)`
* **Signature:** `public final void join(long millis) throws InterruptedException`
* **Description:** Waits at most `millis` milliseconds for the target thread to die. A timeout of `0` means to wait forever.

### D. `void run()`
* **Signature:** `public void run()`
* **Description:** Contains the code that executes when the thread runs. Calling `run()` directly executes in the **current thread** without starting a separate thread of execution.

### E. `void start()`
* **Signature:** `public void start()`
* **Description:** Causes the JVM to create a new execution call stack and invoke the `run()` method in parallel.
* **Throws:** `IllegalThreadStateException` if called more than once on the same thread.

```java
public class InstanceMethodsDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread worker = new Thread(() -> {
            System.out.println("Worker starting...");
            try {
                Thread.sleep(2000);
            } catch (InterruptedException e) {
                System.out.println("Worker interrupted during sleep.");
            }
            System.out.println("Worker finishing...");
        });

        worker.start();
        
        // Wait up to 1 second for worker to complete
        worker.join(1000);
        
        if (worker.isAlive()) {
            System.out.println("Worker taking too long, interrupting...");
            worker.interrupt();
        }
        
        worker.join(); // Wait indefinitely for worker to complete cleanup
        System.out.println("Main finished.");
    }
}
```

## 5. Static Methods

Static methods act on the **currently executing thread** or provide system-wide thread metrics.

### A. `int activeCount()`
* **Signature:** `public static int activeCount()`
* **Description:** Returns an estimate of the number of active threads in the current thread's `ThreadGroup` and its subgroups.

### B. `Thread currentThread()`
* **Signature:** `public static Thread currentThread()`
* **Description:** Returns a reference to the currently executing thread object.

### C. `void yield()`
* **Signature:** `public static void yield()`
* **Description:** Provides a hint to the thread scheduler that the current thread is willing to yield its current use of a processor core to allow other threads equal or higher priority time to run. The scheduler is free to ignore this hint.

### D. `void dumpStack()`
* **Signature:** `public static void dumpStack()`
* **Description:** Prints a stack trace of the current thread to standard error output (`System.err`). Useful for debugging call hierarchies.

```java
public class StaticMethodsDemo {
    public static void main(String[] args) {
        System.out.println("Active threads in group: " + Thread.activeCount());
        
        Thread current = Thread.currentThread();
        System.out.println("Current executing thread: " + current.getName());
        
        System.out.println("Printing current stack trace:");
        Thread.dumpStack();
        
        // Hinting to scheduler to yield execution time slice
        Thread.yield();
    }
}
```

## 6. Thread Starvation

### What is Starvation?
**Starvation** is a concurrency problem where a runnable thread is perpetually denied necessary resources (such as CPU time or monitor locks) and as a result, is unable to make progress.

```
High-Priority Threads:   [Thread-1] ----> [Thread-2] ----> [Thread-3] ----> (Always Scheduled)
                                                                                  |
Low-Priority Thread:    [Starved Thread] ---------------------------------> (Waiting indefinitely)
```

### Common Causes of Starvation:
1. **Thread Priority Abuse:** High-priority threads consume 100% CPU, leaving no time slices for `MIN_PRIORITY` threads.
2. **Synchronized Block Monopolization:** A thread enters a `synchronized` block/method with an infinite or extremely long loop without yielding or sleeping.
3. **Non-Fair Locks:** Using non-fair locking mechanisms (`ReentrantLock(false)`) where newly waiting threads can jump ahead of long-waiting threads.

### Solutions to Starvation:
* **Avoid Priority Manipulation:** Rely on default priorities (`NORM_PRIORITY`) rather than setting custom priorities.
* **Use Fair Locks:** Use `ReentrantLock(true)` which grants locks in a First-In-First-Out (FIFO) order.
* **Bounded Synchronized Work:** Keep `synchronized` blocks as short as possible and avoid long-running operations inside them.
