# Inter-Thread Communication in Java Multithreading


## 1. What is Inter-Thread Communication?

Imagine a restaurant. 
*   **Thread 1 (The Chef):** Cooks the food (Producer).
*   **Thread 2 (The Waiter):** Serves the food to the customer (Consumer).

If the Chef hasn't cooked the food yet, the Waiter shouldn't keep asking every second, *"Is it ready? Is it ready?"* That wastes the Waiter's energy (in computer terms, it wastes CPU time). 

Instead, the Waiter should **wait** quietly. Once the Chef finishes cooking, the Chef will **notify** the Waiter. 

**Inter-Thread Communication** is simply a way for threads to talk to each other. One thread pauses its job and waits, and another thread tells it when to wake up and continue.

---

## 2. Why do we need it? (The Polling Problem)

Without communication, a thread would have to continuously check a condition in a `while` loop. This is called **polling**.

```java
// BAD PRACTICE (Polling)
while (foodIsNotReady) {
    // Keep looping infinitely and waste CPU power!
}
```

To solve this, Java provides three special methods built right into the root `Object` class.

---

## 3. The Three Golden Methods

Because every class in Java inherits from the `Object` class, every object has these three methods:

1.  `wait()`: Tells the current thread to give up the lock and go to sleep until another thread wakes it up.
2.  `notify()`: Wakes up **one** single thread that is waiting on this object's lock.
3.  `notifyAll()`: Wakes up **all** the threads that are waiting on this object's lock.

> **⚠️ VERY IMPORTANT RULE:** 
> You can ONLY call `wait()`, `notify()`, and `notifyAll()` from inside a **`synchronized`** block or method. If you don't, Java will throw an `IllegalMonitorStateException`. You must own the "key" (lock) before you can wait or notify!

## 4. Visual Diagram: How it Works

Let's look at a visual representation of how two threads interact using an object (the shared resource).

```text
+----------------+                       +------------------+
| THREAD 1       |                       | THREAD 2         |
| (Consumer)     |                       | (Producer)       |
+----------------+                       +------------------+
        |                                         |
        | 1. Enters synchronized block            |
        |    (Gets the lock)                      |
        v                                         |
 [ Condition NOT met ]                            |
        |                                         |
        | 2. Calls wait()                         |
        |    (Releases lock & sleeps)             |
        v                                         |
  ( Zzzzz... ) <------------------------+         | 3. Enters synchronized block
                                        |         |    (Gets the lock)
                                        |         v

                                        |         | 4. Calls notify()
  ( WAKES UP ) <------------------------+---------+    (Tells Thread 1 to wake up)
        |                                         |
        | 5. Re-acquires the lock                 | 5. Exits synchronized block
        v                                         |    (Releases the lock)
 [ Condition MET! ]                               v
 Continues working...                     Continues working...
```

## 5. Coding Example: Producer-Consumer

Let's write a simple Java program to show the Chef (Producer) and Waiter (Consumer) in action. We will use a shared object called `Restaurant`.

### Step 1: Create the Shared Resource
```java
class Restaurant {
    private String food;
    // Flag to track if food is ready to be served
    private boolean isFoodReady = false; 

    // Method for the Chef (Producer)
    public synchronized void cookFood(String dishName) {
        // If food is already waiting to be served, the chef must wait
        while (isFoodReady == true) {
            try {
                wait(); // Chef waits
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
        
        // Cook the food
        this.food = dishName;
        System.out.println("Chef cooked: " + dishName);
        
        // Update the flag and notify the Waiter
        isFoodReady = true;
        notify(); // Wakes up the Waiter!
    }

    // Method for the Waiter (Consumer)
    public synchronized void serveFood() {
        // If there is no food ready, the waiter must wait
        while (isFoodReady == false) {
            try {
                wait(); // Waiter waits
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
        
        // Serve the food
        System.out.println("Waiter served: " + this.food);
        
        // Update the flag and notify the Chef to cook the next dish
        isFoodReady = false;
        notify(); // Wakes up the Chef!
    }
}
```

### Step 2: Create the Threads and Run
```java
public class InterThreadDemo {
    public static void main(String[] args) {
        Restaurant restaurant = new Restaurant();

        // Creating the Chef Thread (Producer)
        Thread chef = new Thread(() -> {
            for (int i = 1; i <= 3; i++) {
                restaurant.cookFood("Dish " + i);
            }
        });

        // Creating the Waiter Thread (Consumer)
        Thread waiter = new Thread(() -> {
            for (int i = 1; i <= 3; i++) {
                restaurant.serveFood();
            }
        });

        // Start both threads
        waiter.start(); 
        chef.start();
    }
}
```

### Output:
```text
Chef cooked: Dish 1
Waiter served: Dish 1
Chef cooked: Dish 2
Waiter served: Dish 2
Chef cooked: Dish 3
Waiter served: Dish 3
```
*(Notice how perfectly they take turns? The Chef never cooks dish 2 until the Waiter has served dish 1. This is the magic of inter-thread communication!)*

## 6. Summary and Best Practices

1.  **Always use `while` loop to check conditions, NOT `if`.** 
    Sometimes a thread wakes up by mistake (called a "spurious wakeup"). Using a `while` loop ensures the thread checks the condition again after waking up.
2.  **Locks:** `wait()`, `notify()`, and `notifyAll()` must be inside a `synchronized` context.
3.  **Belongs to `Object`:** These methods belong to the `Object` class, not the `Thread` class, because threads lock on *objects*.
