# Master Class: Understanding Thread States in Java



## 1. What is a Thread State?

In Java, a **Thread** is the smallest unit of execution inside a program. You can think of a Thread as an **individual worker** performing a task.

At any given point in its lifecycle, a thread exists in exactly **one state**. Java's `java.lang.Thread.State` enum defines these **6 lifecycle states**:

| State | Status | Simple Explanation |
| :--- | :--- | :--- |
| **`NEW`** | Not Started | The thread object is created, but `start()` has not been called yet. |
| **`RUNNABLE`** | Active | The thread is ready to run or actively executing CPU instructions. |
| **`BLOCKED`** | Waiting for Lock | The thread is waiting to acquire a monitor lock (e.g., waiting to enter a `synchronized` block). |
| **`WAITING`** | Waiting Indefinitely | The thread is waiting for another thread to perform a specific action without a time limit. |
| **`TIMED_WAITING`** | Waiting with Timeout | The thread is waiting for a specified amount of time (e.g., `Thread.sleep(1000)`). |
| **`TERMINATED`** | Completed | The thread has finished executing its task or died due to an unhandled exception. |

## 3. Deep-Dive: Explanation of Each State

---

### State 1: `NEW`

* **What it means:** A thread has been instantiated using `new Thread()`, but its execution has not begun.
* **Analogy:** Buying a brand-new car and parking it in the garage. Key is not turned yet.
* **How to enter:** Call `new Thread(...)`.
* **How to exit:** Call `.start()` on the thread instance.

```java
Thread thread = new Thread(() -> {
    System.out.println("Running task...");
});
// At this point, thread.getState() returns Thread.State.NEW
```

---

### State 2: `RUNNABLE`

* **What it means:** The thread is active. It is either currently executing Java bytecode on the CPU or waiting in the OS queue for CPU time.
* **Analogy:** Driving the car on the road. Even if you stop briefly at a red light, you are still actively on the journey.
* **Key Detail:** In Java, `RUNNABLE` covers both *Ready to Run* (waiting for CPU allocation) and *Running* (executing on modern CPUs).

```java
thread.start(); 
// Now, thread.getState() returns Thread.State.RUNNABLE
```

---

### State 3: `BLOCKED`

* **What it means:** The thread wants to execute a `synchronized` block or method, but another thread is currently holding that lock. The blocked thread pauses until the lock is released.
* **Analogy:** Waiting in line outside a single-occupancy restroom because someone else inside locked the door.

```java
public synchronized void criticalSection() {
    // Thread A enters here.
    // Thread B trying to enter will be in the BLOCKED state until Thread A finishes.
}
```

---

### State 4: `WAITING`

* **What it means:** The thread is waiting indefinitely for another thread to send a signal or notification before it can proceed.
* **Analogy:** Sitting in a restaurant waiting for the waiter to bring your meal. You don't know the exact minute it will arrive, so you wait until called.
* **Common Trigger Methods:**
  * `object.wait()`
  * `thread.join()` (without timeout)
  * `LockSupport.park()`

```java
synchronized(sharedObject) {
    // Thread releases lock and waits until another thread calls sharedObject.notify()
    sharedObject.wait(); 
}
```

---

### State 5: `TIMED_WAITING`

* **What it means:** The thread is pausing execution for a predefined duration. Once the timer expires (or it gets notified early), it transitions back to `RUNNABLE`.
* **Analogy:** Setting an alarm clock for 30 minutes to take a power nap.
* **Common Trigger Methods:**
  * `Thread.sleep(milliseconds)`
  * `object.wait(milliseconds)`
  * `thread.join(milliseconds)`

```java
try {
    // Thread pauses execution for 2 seconds (2000 milliseconds)
    Thread.sleep(2000); 
} catch (InterruptedException e) {
    e.printStackTrace();
}
```

---

### State 6: `TERMINATED` (or DEAD)

* **What it means:** The thread has completed running its code inside the `run()` method, or it terminated abruptly due to an unhandled exception/error.
* **Analogy:** Arriving at your destination and turning off the car engine. The trip is complete.
* **Note:** A terminated thread cannot be restarted! Calling `start()` on a terminated thread throws an `IllegalThreadStateException`.

## 4. Complete Java Program Demonstrating All States

Here is a working program that demonstrates how to inspect different thread states programmatically:

```java
public class ThreadStateDemo {

    private static final Object lock = new Object();

    public static void main(String[] args) throws InterruptedException {

        // 1. NEW STATE
        Thread workerThread = new Thread(() -> {
            try {
                // 5. TIMED_WAITING STATE
                Thread.sleep(1000);

                synchronized (lock) {
                    // 4. WAITING STATE
                    lock.wait();
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });

        System.out.println("State after creation: " + workerThread.getState()); // NEW

        // 2. RUNNABLE STATE
        workerThread.start();
        System.out.println("State after calling start(): " + workerThread.getState()); // RUNNABLE

        // Give workerThread time to enter Thread.sleep()
        Thread.sleep(200);
        System.out.println("State while sleeping: " + workerThread.getState()); // TIMED_WAITING

        // Give workerThread time to finish sleeping and call wait()
        Thread.sleep(1000);
        System.out.println("State while waiting on lock.wait(): " + workerThread.getState()); // WAITING

        // Wake up the workerThread
        synchronized (lock) {
            lock.notify();
        }

        // Wait for workerThread to finish executing
        workerThread.join();

        // 6. TERMINATED STATE
        System.out.println("State after execution completes: " + workerThread.getState()); // TERMINATED
    }
}
```

### Expected Console Output:

```text
State after creation: NEW
State after calling start(): RUNNABLE
State while sleeping: TIMED_WAITING
State while waiting on lock.wait(): WAITING
State after execution completes: TERMINATED
```

---

## 5. Quick Reference & Summary

1. **`NEW`**: Created, but `start()` not called.
2. **`RUNNABLE`**: Running or ready to run in the thread queue.
3. **`BLOCKED`**: Waiting to enter a `synchronized` lock block.
4. **`WAITING`**: Paused indefinitely using `wait()` or `join()`.
5. **`TIMED_WAITING`**: Paused for a specific time using `sleep()` or `wait(timeout)`.
6. **`TERMINATED`**: Execution complete or thrown exception.
