# Java Multithreading: Understanding Synchronization



Before we jump into synchronization, let's quickly remember what multithreading is. In Java, a **Thread** is like a small worker doing a task. **Multithreading** means we have many workers (threads) doing tasks at the very same time.

---

## 1. The Problem: Why do we need Synchronization?

Imagine you and your friend share a **Joint Bank Account** with $100 in it. 
* **Worker A (You):** Goes to an ATM to withdraw $100.
* **Worker B (Your Friend):** Goes to another ATM at the exact same time to withdraw $100.

If both ATMs check the balance at the exact same millisecond, they both see $100. They both allow the withdrawal. Now the bank has lost $100 because the account went into negative, but the system didn't catch it!

In Java, when multiple threads try to read and change the **same shared data** at the same time, they can step on each other's toes. This creates wrong results. We call this a **Race Condition** or **Thread Interference**.

---

## 2. The Solution: What is Synchronization?

**Synchronization** is a way to control the access of multiple threads to any shared resource (like our bank account). 

Think of Synchronization like a **public washroom with only one key**. 
If Thread A wants to use the washroom, it takes the key, goes inside, and locks the door. If Thread B arrives, it must **wait** outside until Thread A comes out and returns the key. 

In Java, this "key" is called an **Intrinsic Lock** or **Monitor**. Every object in Java has one built-in lock.

### Visual Diagram of Synchronization

```text
[ Shared Object (e.g., Bank Account) ] --- HAS 1 LOCK (🔑)

Thread 1 🏃‍♂️ -----------> Grabs 🔑 -----------> [ Inside Method: Working... ]
                                                       |
Thread 2 🏃‍♀️ ---> Tries to enter ---> No 🔑? ---> [ WAITING LINE 🧍‍♀️🧍‍♂️ ]
Thread 3 🏃‍♂️ ---> Tries to enter ---> No 🔑? ---> [ WAITING LINE 🧍‍♀️🧍‍♂️ ]
                                                       |
Thread 1 finishes <------------------------------------+
Thread 1 returns 🔑!

Now Thread 2 grabs the 🔑 and enters!
```

## 3. How to use Synchronization in Java

There are two main ways to use synchronization in Java. 

### Method A: Synchronized Method
You simply add the word `synchronized` to your method. If a method is synchronized, a thread must get the object's lock before it can execute the method.

**Syntax:**
```java
public synchronized void myMethod() {
    // Shared data logic here
}
```

**Example Code:**
Let's look at a simple Counter. We want to increase the count by 1.

```java
class Counter {
    int count = 0;

    // The 'synchronized' keyword locks this method.
    // Only one thread can run this at a time!
    public synchronized void increment() {
        count = count + 1; 
    }
}

public class Main {
    public static void main(String[] args) throws Exception {
        Counter myCounter = new Counter();

        // Thread 1
        Thread t1 = new Thread(() -> {
            for(int i=0; i<1000; i++) {
                myCounter.increment();
            }
        });

        // Thread 2
        Thread t2 = new Thread(() -> {
            for(int i=0; i<1000; i++) {
                myCounter.increment();
            }
        });

        t1.start();
        t2.start();

        t1.join(); // Wait for t1 to finish
        t2.join(); // Wait for t2 to finish

        // Because of synchronization, the result will safely be exactly 2000!
        System.out.println("Final Count: " + myCounter.count); 
    }
}
```

### Method B: Synchronized Block
Sometimes, your method has 100 lines of code, but only 2 lines actually touch the shared data. Locking the whole 100-line method makes other threads wait too long (which slows down your program). 

Instead, you can lock *only* the specific lines of code using a **Synchronized Block**.

**Syntax:**
```java
public void myMethod() {
    // Normal code that multiple threads can run at the same time
    System.out.println("Hello from thread!"); 

    // Lock only this block! 'this' means we are using the lock of the current object.
    synchronized(this) {
        // Shared data logic here
    }
    
    // More normal code
}
```

## 4. Related Important Topics

As a beginner, if you understand Synchronization, you should also know these two related concepts:

### 1. Volatile Keyword
Sometimes, threads keep a local copy of a variable in their own small memory (cache) to work faster. If Thread A changes the variable, Thread B might not see the change immediately. 
If you mark a variable as `volatile`, you are telling Java: *"Do not cache this! Always read and write this directly to the main memory."*
* **Note:** `volatile` is only for visibility, it does NOT lock data like `synchronized` does.

### 2. Deadlock (The Danger of Synchronization)
Imagine two people at a dinner table. Person A has a fork and needs a knife. Person B has a knife and needs a fork. Neither will let go of what they have until they get the other tool. They will sit there forever!
In Java, **Deadlock** happens when Thread 1 holds Lock A and is waiting for Lock B, while Thread 2 holds Lock B and is waiting for Lock A. When using synchronization, we must be careful not to lock too many things at once to avoid deadlocks.
