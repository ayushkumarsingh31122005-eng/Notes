# Creating Threads in Java: Thread Class vs. Runnable Interface

 

In Java, the creators gave us **two different ways** to build a Thread:
1. Extending the `Thread` Class.
2. Implementing the `Runnable` Interface.

Let's break them down in simple English with real-world analogies, visuals, and beginner-friendly code!

---

## 1. Way Number One: Extending the `Thread` Class

**The Concept:** 
Java has a built-in class called `Thread`. If you want to make your own custom thread, you can just tell your class to "inherit" or "extend" this built-in `Thread` class. 

**Real-Life Analogy:**
Imagine you want to hire a specialized worker to paint your house. You hire a "Professional Painter." Because they are born as a painter (they extended the Painter class), they already know how to paint. But because they are *only* a painter, they cannot be an electrician at the same time.

**Visual Diagram:**
```text
  [ Built-in Java Thread Class ]
               ^
               | (extends)
               |
  [ Your Custom Worker Class ] 
   - Overrides the run() method
```

### How to do it (Syntax & Code):

There are exactly 3 steps to do this:
1. Create a class and add `extends Thread`.
2. Write a `public void run()` method inside it. This is where you put the job the worker needs to do.
3. Create an object of your class and call `.start()`.

```java
// Step 1: Extend the Thread class
class MyPaintingThread extends Thread {
    
    // Step 2: Override the run() method
    @Override
    public void run() {
        System.out.println("Worker 1 is painting the house...");
        for(int i=1; i<=3; i++) {
            System.out.println("Painting wall " + i);
        }
    }
}

public class ThreadClassExample {
    public static void main(String[] args) {
        // Step 3: Create the object and start it
        MyPaintingThread painter = new MyPaintingThread();
        painter.start(); // This automatically calls the run() method in the background!
    }
}
```

## 2. Way Number Two: Implementing the `Runnable` Interface

**The Concept:**
An "Interface" in Java is like a contract or an instruction manual. The `Runnable` interface just says, "Whoever signs this contract MUST have a `run()` method." 
Instead of *being* a Thread, your class just holds the *instructions* (the Runnable task). You then hand those instructions to a blank, standard Thread worker to execute.

**Real-Life Analogy:**
Instead of hiring a specialized painter, you write a "To-Do List" (the Runnable). You then hand this To-Do List to a general Worker (the Thread). The great thing about this? The general worker can also read other instruction manuals if they want to!

**Visual Diagram:**
```text
  [ Runnable Interface (Contract) ]
               ^
               | (implements)
               |
  [ Your Task Class ] ------(hands task to)-----> [ Standard Java Thread ]
   - Provides the run() method                           - Executes the task
```

### How to do it (Syntax & Code):

There are 4 steps here:
1. Create a class and add `implements Runnable`.
2. Write the `public void run()` method.
3. Create an object of your task class.
4. Create a standard Java `Thread`, give it your task object, and call `.start()`.

```java
// Step 1: Implement the Runnable interface
class ElectricianTask implements Runnable {
    
    // Step 2: Provide the run() method
    @Override
    public void run() {
        System.out.println("Worker 2 is fixing the wires...");
        for(int i=1; i<=3; i++) {
            System.out.println("Fixing wire " + i);
        }
    }
}

public class RunnableExample {
    public static void main(String[] args) {
        // Step 3: Create your task object (The To-Do List)
        ElectricianTask myTask = new ElectricianTask();
        
        // Step 4: Create a standard Thread, hand it the task, and start!
        Thread worker = new Thread(myTask); 
        worker.start(); 
    }
}
```

## 3. The Big Question: Which one is better?

As a Senior Developer, I will tell you a secret: **Implementing `Runnable` is almost always better!**

Why? 
Because Java has a strict rule called **"No Multiple Inheritance."** A class in Java can only `extend` ONE single parent class. 

* **If you use `extends Thread`:** Your class has used up its one and only chance to have a parent. It cannot extend any other useful class.
* **If you use `implements Runnable`:** Your class is free! It can extend another parent class (like an `Employee` class or a `GameCharacter` class) AND still implement `Runnable` to be a thread. Interfaces are very flexible.

### Summary Comparison:

| Feature | `extends Thread` | `implements Runnable` |
| :--- | :--- | :--- |
| **Inheritance limit** | Uses up your 1 class extension. | Free to extend other classes! |
| **Memory** | Creates a whole new Thread object. | Shares the same task object among threads. |
| **Industry Standard** | Used mostly for quick, simple tests. | **Highly recommended** by professionals. |
