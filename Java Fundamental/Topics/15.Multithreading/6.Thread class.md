# Master Class: The `java.lang.Thread` Class in Java

The **`Thread` class** is the core foundation of multithreading in Java. Belonging to the `java.lang` package, it represents an independent path of execution within a program.

In this guide, we will explore the internal architecture of the `Thread` class, its key constructors and methods, different ways to create threads, and essential thread control mechanisms.

---

## 1. Hierarchy and Core Interfaces

The `Thread` class implements the **`Runnable`** interface, which defines a single method: `public void run()`.

```
                    +-------------------+
                    |  java.lang.Object |
                    +-------------------+
                              |
                              v
   +-------------------+     +--------------------+
   |     Runnable      | <-- |  java.lang.Thread  |
   |   (Interface)     |     |      (Class)       |
   +-------------------+     +--------------------+
             |
     defines run()
```

### Key Interfaces Implemented by `Thread`:
* **`Runnable`**: Defines the task code that will execute in the thread (`run()`).
* **`UncaughtExceptionHandler`**: Interface nested inside `Thread` to handle uncaught exceptions thrown during execution.

---

## 2. Ways to Create a Thread

There are two primary traditional ways to create and instantiate a `Thread` in Java, along with modern functional approaches.

### Approach 1: Extending the `Thread` Class

Override the `run()` method directly inside a subclass.

```java
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("Executing task in: " + Thread.currentThread().getName());
    }
}

public class Main {
    public static void main(String[] args) {
        MyThread t1 = new MyThread();
        t1.start(); // Starts execution in a new call stack
    }
}
```

---

### Approach 2: Implementing the `Runnable` Interface (Recommended)

Pass a `Runnable` object into the `Thread` constructor. This decouples the task logic from the thread execution mechanism.

```java
class MyTask implements Runnable {
    @Override
    public void run() {
        System.out.println("Task running in: " + Thread.currentThread().getName());
    }
}

public class Main {
    public static void main(String[] args) {
        Thread t1 = new Thread(new MyTask(), "Worker-Thread-1");
        t1.start();
    }
}
```

---

### Approach 3: Using Lambda Expressions (Java 8+)

Since `Runnable` is a functional interface, you can pass a lambda expression directly:

```java
Thread t1 = new Thread(() -> {
    System.out.println("Lambda thread running: " + Thread.currentThread().getName());
}, "LambdaWorker");

t1.start();
```

## 3. Crucial `Thread` Constructors

| Constructor | Description |
| --- | --- |
| `Thread()` | Default constructor creating an unassigned thread. |
| `Thread(String name)` | Creates a thread with a custom name. |
| `Thread(Runnable target)` | Creates a thread wrapping a specific `Runnable` task. |
| `Thread(Runnable target, String name)` | Creates a thread wrapping a `Runnable` task with a specific name. |
| `Thread(ThreadGroup group, Runnable target, String name)` | Assigns thread to a specific `ThreadGroup`. |

## 4. Key Instance Methods of the `Thread` Class

```
                           Thread Execution Controls
   +-----------------------------------------------------------------------+
   |  start()         --> Tells JVM to create stack frame & execute run()   |
   |  join()          --> Pauses current thread until target completes     |
   |  interrupt()     --> Sends interrupt signal to target thread          |
   |  setDaemon(bool) --> Marks thread as user or background daemon        |
   +-----------------------------------------------------------------------+
```

### 1. `start()` vs `run()`

* **`start()`**: Allocates a new call stack frame in OS memory and moves the thread to `RUNNABLE` state, triggering `run()`.
* **`run()`**: A normal method call! Calling `run()` directly **does not start a new thread**; it runs sequentially inside the current thread's call stack.

```java
Thread t = new Thread(() -> System.out.println(Thread.currentThread().getName()));

t.run();   // Output: main (Runs in the calling thread)
t.start(); // Output: Thread-0 (Runs in a separate concurrent thread)
```

---

### 2. `join()` and `join(long millis)`

Pauses the caller thread until the target thread finishes execution.

```java
Thread t1 = new Thread(() -> {
    try { Thread.sleep(1000); } catch (InterruptedException e) {}
    System.out.println("Task completed.");
});

t1.start();
t1.join(); // Main thread waits here until t1 completes execution
System.out.println("Main thread resumes execution.");
```

---

### 3. `interrupt()` and `isInterrupted()`

Used to signal a thread that it should stop its current work.

* **`interrupt()`**: Sets the interrupt flag on the target thread.
* **`isInterrupted()`**: Checks if the interrupt flag is set (`true`/`false`).
* **`interrupted()` (static)**: Checks the flag and **clears** it back to `false`.

```java
Thread worker = new Thread(() -> {
    while (!Thread.currentThread().isInterrupted()) {
        System.out.println("Working...");
    }
    System.out.println("Thread interrupted gracefully.");
});

worker.start();
worker.interrupt(); // Requests worker thread to stop
```

---

### 4. `setDaemon(boolean on)` & `isDaemon()`

* **User Threads**: High-priority application threads. The JVM will **not exit** until all user threads complete.
* **Daemon Threads**: Background service threads (e.g., Garbage Collector). The JVM exits immediately if only daemon threads remain active.

```java
Thread daemonThread = new Thread(() -> {
    while (true) {
        System.out.println("Background logging...");
    }
});

daemonThread.setDaemon(true); // Must be set BEFORE start()
daemonThread.start();
```

> ⚠️ **Note:** Calling `setDaemon(true)` after `start()` will throw an `IllegalThreadStateException`.

---

## 5. Important Static Methods

Static methods act on the **currently executing thread**:

| Static Method | Description |
| --- | --- |
| `Thread.currentThread()` | Returns a reference to the thread executing the line of code. |
| `Thread.sleep(long millis)` | Suspends current thread for given duration without releasing lock monitors. |
| `Thread.yield()` | Hints to OS scheduler that current thread is willing to yield CPU time slice. |
| `Thread.holdsLock(Object obj)` | Returns `true` if current thread holds monitor lock on `obj`. |

## 6. Comprehensive Code Example

Here is a complete program demonstrating creation, naming, sleep, joining, daemon threads, and handling uncaught exceptions using the `Thread` class:

```java
public class ThreadClassDemo {

    public static void main(String[] args) throws InterruptedException {

        // 1. Current Thread
        System.out.println("Current thread: " + Thread.currentThread().getName());

        // 2. Creating a Worker Thread
        Thread worker = new Thread(() -> {
            System.out.println(Thread.currentThread().getName() + " started.");
            try {
                Thread.sleep(1000); // Sleep for 1 second
            } catch (InterruptedException e) {
                System.out.println("Thread was interrupted.");
            }
            System.out.println(Thread.currentThread().getName() + " finished.");
        }, "Worker-Thread");

        // 3. Uncaught Exception Handler
        worker.setUncaughtExceptionHandler((t, e) -> {
            System.err.println("Exception in thread " + t.getName() + ": " + e.getMessage());
        });

        // 4. Daemon Thread Setup
        Thread daemon = new Thread(() -> {
            while (true) {
                try {
                    Thread.sleep(300);
                    System.out.println("[Daemon] Heartbeat running...");
                } catch (InterruptedException e) {
                    break;
                }
            }
        });
        daemon.setDaemon(true);
        daemon.start();

        // Start worker and wait for completion
        worker.start();
        worker.join(); // Wait for worker to finish

        System.out.println("Main thread exiting...");
    }
}
```

## 7. Summary Checklist

1. Always prefer **`Runnable`** or **Lambdas** over extending `Thread` class to keep code decoupled.
2. Call **`start()`**, never `run()`, when launching parallel execution threads.
3. Configure **`setDaemon(true)`** strictly before calling `start()`.
4. Handle **`InterruptedException`** clean-up responsibly when invoking blocking methods like `sleep()` or `join()`.
