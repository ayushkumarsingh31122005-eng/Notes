# Deep-Dive: Thread Priority in Java Multithreading


## 1. What is Thread Priority?

In a multithreaded Java application, multiple threads often compete for access to a limited resource: **CPU time**.

**Thread Priority** is an integer value assigned to a `Thread` instance that serves as a **hint** to the **Java Virtual Machine (JVM)** and the underlying **Operating System (OS) Scheduler** about which thread should be prioritized when allocating CPU cycles.

### Key Conceptual Takeaway
> **Priority is a hint, not a guarantee.**
> Thread scheduling in Java is predominantly **preemptive** and depends heavily on the host OS platform (Windows, Linux, macOS).

---
### Java support priority from 1 to 10.

## 2. Priority Range and Constants

In Java, thread priorities are represented by integer values ranging from **1 (lowest)** to **10 (highest)**.

The `java.lang.Thread` class defines three primary static constants for priority:

| Constant | Value | Description |
| :--- | :--- | :--- |
| **`Thread.MIN_PRIORITY`** | `1` | Lowest priority a thread can have. |
| **`Thread.NORM_PRIORITY`** | `5` | Default priority assigned to threads (unless inherited otherwise). |
| **`Thread.MAX_PRIORITY`** | `10` | Highest priority a thread can have. |

```
Priority Scale in Java:
[ MIN_PRIORITY = 1 ] <--- 2 --- 3 --- 4 ---> [ NORM_PRIORITY = 5 ] <--- 6 --- 7 --- 8 --- 9 ---> [ MAX_PRIORITY = 10 ]
```

---

## 3. How Thread Priority Inheritance Works

When a new thread is created, it **inherits its priority from the parent thread** that created it.

### Inheritance Rules:
1. The `main` thread is created by the JVM and defaults to priority **5 (`NORM_PRIORITY`)**.
2. Any thread spawned from the `main` thread will inherit priority **5** by default.
3. If Thread A (priority 8) creates Thread B, Thread B will initially have priority **8**.

```
                   +------------------------------------+
                   |    Main Thread (Priority: 5)       |
                   +------------------------------------+
                                     |
                Creates Thread-A     |     Creates Thread-B
                (Priority set to 8)  |     (No priority set)
                                     v
         +----------------------+        +----------------------+
         | Thread-A             |        | Thread-B             |
         | Priority: 8          |        | Priority: 5          |
         +----------------------+        +----------------------+
                    |
             Creates Thread-C
             (No priority set)
                    v
         +----------------------+
         | Thread-C             |
         | Priority: 8 (Inherit)|
         +----------------------+
```

## 4. Key Methods for Thread Priority

The `java.lang.Thread` class provides two core instance methods to interact with thread priority:

### 1. `setPriority(int newPriority)`
Sets the priority of the thread.

* **Signature:** `public final void setPriority(int newPriority)`
* **Validation:** If `newPriority` is `< 1` or `> 10`, it throws an `IllegalArgumentException`.
* **Security Check:** May throw a `SecurityException` if the current thread cannot modify the target thread.

### 2. `getPriority()`
Returns the priority of the thread.

* **Signature:** `public final int getPriority()`
* **Return Type:** `int` (between 1 and 10).

---

## 5. Thread Group Priority Constraints

If a thread belongs to a **`ThreadGroup`**, its effective maximum priority is restricted by the group's maximum priority limit.

```java
ThreadGroup group = new ThreadGroup("CustomGroup");
group.setMaxPriority(7); // Max allowed in group is 7

Thread t = new Thread(group, "MyThread");
t.setPriority(10); // Attempting to set priority to 10

System.out.println(t.getPriority()); // Output: 7 (Capped by ThreadGroup)
```

> **Rule:** A thread's priority cannot exceed the maximum priority allowed by its `ThreadGroup`.

## 6. How the OS Scheduler Interacts with Java Priorities

This is where reality diverges from theory.

Java delegates thread execution to the underlying **Operating System Native Scheduler**. Different operating systems map Java's 1-10 priority scale differently to their internal priority scales.

### OS Priority Mapping Examples:

1. **Windows OS:**
   * Windows has 7 native thread priority levels (`THREAD_PRIORITY_LOWEST` to `THREAD_PRIORITY_TIME_CRITICAL`).
   * Java's 1-10 values map cleanly onto these 7 native levels (some Java priorities map to the same OS priority level).

2. **Linux OS:**
   * Linux uses a `nice` value mechanism (ranging from -20 to +19) or real-time priority schedulers (`SCHED_FIFO`, `SCHED_RR`).
   * On many Linux JVM implementations (like Standard OpenJDK running without root privileges), **Java thread priorities are ignored completely**. All threads run with equal native scheduling priority.

3. **macOS (Unix/POSIX):**
   * Uses Mach/BSD scheduling threads. Priority hints may affect execution order slightly, but preemption remains OS-driven.

## 7. Comprehensive Code Example

Here is a complete Java program demonstrating priority configuration, inheritance, and behavior during high CPU-bound processing:

```java
public class ThreadPriorityDemo {

    public static void main(String[] args) {
        // 1. Check Main Thread Priority
        Thread mainThread = Thread.currentThread();
        System.out.println("Main Thread Name: " + mainThread.getName());
        System.out.println("Main Thread Priority: " + mainThread.getPriority()); // Default: 5

        // 2. Priority Inheritance Demo
        mainThread.setPriority(8);
        Thread childThread = new Thread(new HeavyTask(), "Child-Thread");
        System.out.println(childThread.getName() + " Inherited Priority: " + childThread.getPriority()); // Inherits: 8

        // Reset main thread priority
        mainThread.setPriority(Thread.NORM_PRIORITY);

        // 3. Demonstrating High vs Low Priority Execution
        Thread minPriorityWorker = new Thread(new HeavyTask(), "Min-Priority-Worker");
        Thread maxPriorityWorker = new Thread(new HeavyTask(), "Max-Priority-Worker");

        minPriorityWorker.setPriority(Thread.MIN_PRIORITY); // Priority 1
        maxPriorityWorker.setPriority(Thread.MAX_PRIORITY); // Priority 10

        System.out.println("\n--- Starting High vs Low Priority Execution Test ---");
        minPriorityWorker.start();
        maxPriorityWorker.start();
    }
}

class HeavyTask implements Runnable {
    @Override
    public void run() {
        long count = 0;
        long startTime = System.currentTimeMillis();

        // Perform a CPU-heavy computation
        for (long i = 0; i < 1_000_000_000L; i++) {
            count++;
        }

        long endTime = System.currentTimeMillis();
        System.out.println(Thread.currentThread().getName() 
                + " (Priority: " + Thread.currentThread().getPriority() + ")"
                + " finished in " + (endTime - startTime) + " ms.");
    }
}
```

## 8. Critical Concepts & Edge Cases

### A. Thread Starvation
* **Problem:** If high-priority threads are constantly running, low-priority threads may **never get CPU time**.
* **Result:** Low-priority threads get "starved."
* **OS Solution:** Modern OS schedulers use time-slicing and temporary priority boosting to prevent starvation, but it remains a design risk in Java applications.

### B. Priority Inversion
* **Scenario:**
  1. Low-Priority Thread `T1` holds a shared lock.
  2. High-Priority Thread `T3` needs that lock and goes to `BLOCKED` state.
  3. Medium-Priority Thread `T2` (does not need the lock) preempts `T1` because `Priority(T2) > Priority(T1)`.
* **Issue:** `T2` delays `T1`, which indirectly holds up `T3`. The high-priority thread `T3` ends up waiting on a medium-priority thread `T2`.
* **Fix:** Synchronization constructs (like `ReentrantLock`) and OS schedulers use **Priority Inheritance Protocols** to temporarily elevate `T1`'s priority to `T3`'s level until it releases the lock.

---

## 9. Summary & Real-World Best Practices

| Scenario | Best Practice |
| :--- | :--- |
| **General Logic** | Do **NOT** rely on `setPriority()` for critical application correctness or thread ordering. |
| **OS Independence** | Assume priority behavior is non-deterministic across platforms (Windows vs. Linux). |
| **Thread Control** | Use explicit concurrency tools like `CountDownLatch`, `Semaphore`, `ReentrantLock`, or `ExecutorService` instead of priorities to sequence thread execution. |
| **Valid Use Case** | Priority hints are acceptable for background non-critical tasks (e.g., log flushing, garbage collection hints, metrics collection) set to `MIN_PRIORITY`. |
