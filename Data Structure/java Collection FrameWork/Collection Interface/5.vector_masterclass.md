# Master Vectors: 

 

To understand a Vector, you first need to understand the limitations of a standard Array. A normal Array in Java has a fixed size. If you create an array of size 5, and try to add a 6th item, your program will crash. 

A **Vector** is a **Dynamic Array**. It acts exactly like an array, but it can grow and shrink automatically as you add or remove items.

## 1. What makes Vector special? (The "Thread-Safe" Concept)

Before we look at code, let's understand the two biggest rules of a Vector:

1. **It is Dynamic:** It resizes itself automatically.
2. **It is Synchronized (Thread-Safe):** This is its most defining feature. Imagine you are working at Google, and a millions of users are trying to add data to a list at the *exact same millisecond* (this is called Multi-threading). A Vector locks itself so that only **one thread (one task) can modify it at a time**. This prevents data from getting corrupted.

### Visual Diagram: How Vector Resizes

By default, when you create a Vector, it creates an empty array inside itself with a **capacity of 10**. 

What happens when it gets full? **It doubles its size (100% increase)!**

```text
Step 1: Vector is created (Capacity: 10, Size: 0)
[ ][ ][ ][ ][ ][ ][ ][ ][ ][ ]

Step 2: We add 10 items. It is now FULL. (Capacity: 10, Size: 10)
[A][B][C][D][E][F][G][H][I][J]

Step 3: We try to add an 11th item ('K').
The Vector secretly creates a NEW array double the size (20), 
copies the old data over, and adds 'K'.

[A][B][C][D][E][F][G][H][I][J][K][ ][ ][ ][ ][ ][ ][ ][ ][ ]
```
* **Size:** How many items are actually inside.
* **Capacity:** How many items it can hold before it needs to resize again.

## 2. How to Initialize a Vector

Java gives us several ways to build a Vector, depending on how much control we want over its capacity.

```java
import java.util.Vector;

public class VectorInitialization {
    public static void main(String[] args) {
        
        // Way 1: Default (Capacity is 10)
        Vector<Integer> v1 = new Vector<>();
        
        // Way 2: Custom Initial Capacity (You know you need 50 spots)
        Vector<String> v2 = new Vector<>(50);
        
        // Way 3: Capacity AND Increment 
        // Start with 10 spots. When full, add 5 more spots (instead of doubling).
        Vector<Double> v3 = new Vector<>(10, 5); 
    }
}
```

## 3. Core Vector Methods

Here are the most common methods you will use. Because Vector is very old (it was in Java 1.0!), it has some older method names like `addElement()`, but it also supports modern list methods like `add()`.

| Method Name | What it does | Time Complexity | 
| ----- | ----- | ----- | 
| `add(Element e)` | Appends the specified element to the end. | Amortized $O(1)$ | 
| `add(int index, Element e)` | Inserts at a specific position. Shifts others right. | $O(N)$ | 
| `get(int index)` | Returns the element at the specified position. | $O(1)$ | 
| `remove(int index)` | Removes the element at the position. Shifts others left. | $O(N)$ | 
| `size()` | Returns the number of elements actually in the Vector. | $O(1)$ | 
| `capacity()` | Returns the current total room inside the Vector. | $O(1)$ | 

## 4. Complete Code Example

Let's see it in action:

```java
import java.util.Vector;

public class VectorDemo {
    public static void main(String[] args) {
        // Create a Vector of Strings
        Vector<String> techCompanies = new Vector<>();

        // 1. Adding elements
        techCompanies.add("Google");
        techCompanies.add("Microsoft");
        techCompanies.add("Facebook"); // Same as Meta

        System.out.println("Companies: " + techCompanies);
        // Output: [Google, Microsoft, Facebook]

        // 2. Getting an element (Fast!)
        System.out.println("Company at index 1: " + techCompanies.get(1));
        // Output: Microsoft

        // 3. Size vs Capacity
        System.out.println("Size (items inside): " + techCompanies.size());       // Output: 3
        System.out.println("Capacity (total room): " + techCompanies.capacity()); // Output: 10

        // 4. Removing an element
        techCompanies.remove(2); // Removes Facebook
        
        System.out.println("After removal: " + techCompanies);
        // Output: [Google, Microsoft]
    }
}
```

## 5. 🚨 FAANG Interview Reality Check: Vector vs ArrayList 🚨

If you are in an interview at Microsoft or Google and the interviewer asks: 
*"I need you to store a dynamic list of numbers. Should you use a Vector or an ArrayList?"*

**Your Answer MUST be:** "I will use an **ArrayList**."

### Why?
`Vector` and `ArrayList` do the exact same thing (they are both dynamic arrays). However:

1. **Speed:** Because `Vector` is **Synchronized** (thread-safe), it locks the data every time you read or write to it. This locking mechanism takes time and makes Vector **much slower** than ArrayList. 
2. **Growth Factor:** When full, Vector doubles in size (100% growth). ArrayList only grows by 50%. ArrayList is better at saving computer memory.

**In modern DSA interviews, you almost NEVER write code for multi-threaded environments unless specifically asked.** Therefore, always use `ArrayList` instead of `Vector` for dynamic arrays. 

## 6. Time and Space Complexity (Summary)

Just like an ArrayList, a Vector relies on an array under the hood.

* **Access by Index (`get`):** $O(1)$ - Extremely fast.
* **Insert at End (`add`):** Usually $O(1)$. However, if the Vector is full, it takes $O(N)$ time to create the new double-sized array and copy the old items over. We call this "Amortized $O(1)$".
* **Insert/Delete in the Middle:** $O(N)$ - Because you have to physically shift all the elements to the right or left to make room or fill the gap.
* **Space Complexity:** $O(N)$ - It takes memory proportional to the number of items you store.
