# The Ultimate Showdown: ArrayList vs LinkedList vs Vector vs Stack

 golden interview question: *"If they all implement the List Interface, how are they different?"*

To understand this, we must first understand what an **Interface** is. 
Think of the `List` interface as a **contract**. The contract says: *"Anyone who signs this must have an `add()` method, a `get()` method, and a `remove()` method."*

`ArrayList`, `LinkedList`, `Vector`, and `Stack` all signed this contract. So, you can add, get, and remove items from all of them. However, *how* they do those tasks behind the scenes is completely different.

## 1. The Family Tree (Class Hierarchy)

Here is a simple map of how these classes are related in Java:

```text
                  [ Interface: List ]
                           |
      -------------------------------------------
      |                    |                    |
[ ArrayList ]        [ LinkedList ]         [ Vector ]
 (Uses Array)         (Uses Nodes)         (Uses Array)
                                                |
                                            [ Stack ]
                                         (Extends Vector)
```

Now, let's look at the "engine" inside each one.

## 2. ArrayList: The Speed Reader
**The Engine:** A standard, resizable Array. 
Memory is stored continuously (right next to each other).

* **How it works:** When you create an `ArrayList`, it creates a hidden array. If it gets full, it creates a new array that is **50% larger** and copies the items over.
* **Superpower:** **Reading data.** Because memory is continuous, if you ask for `get(500)`, the computer knows exactly where to jump instantly ($O(1)$ time).
* **Weakness:** **Inserting/Deleting in the middle.** If you want to insert an item at index 0, every single other item has to be shifted one space to the right ($O(N)$ time).

## 3. LinkedList: The Train
**The Engine:** Doubly Linked Nodes. 
Memory is scattered randomly, connected by pointers.

* **How it works:** Each item (node) only knows about the item in front of it and the item behind it.
* **Superpower:** **Inserting/Deleting at the ends or middle.** If you insert an item, you don't shift anything. You just break two links and connect the new node ($O(1)$ time if you are already at that position).
* **Weakness:** **Reading data.** If you ask for `get(500)`, the computer cannot jump there. It must start at node 0 and walk node-by-node until it reaches 500 ($O(N)$ time).

## 4. Vector: The Overprotective Grandparent
**The Engine:** A resizable Array (exactly like ArrayList).

* **How it works:** It works just like `ArrayList`, but when it gets full, it grows by **100%** (doubles in size). 
* **Superpower:** **Thread-Safety (Synchronization).** Only one process can use it at a time.
* **Weakness:** **Speed.** Because it constantly locks and unlocks itself to be safe, it is much slower than `ArrayList`. 
* **FAANG Note:** It is considered a "Legacy" (old) class. Modern developers use `ArrayList` instead.

## 5. Stack: The LIFO Bucket
**The Engine:** It extends `Vector`, so it also uses a resizable Array underneath.

* **How it works:** It enforces the **LIFO (Last In, First Out)** rule. You only interact with the "Top" of the stack.
* **Superpower:** Reversing data, tracking history (like an Undo button), and solving maze puzzles (DFS).
* **Weakness:** Because it extends `Vector`, it is also slow and synchronized. 
* **FAANG Note:** Modern developers use `ArrayDeque` when they need a Stack!

## 6. The Ultimate Comparison Table

Memorize this table for your interviews. It compares how fast they are (Time Complexity).

| Operation | ArrayList | LinkedList | Vector | Stack |
| :--- | :--- | :--- | :--- | :--- |
| **get(index)** (Read) | **$O(1)$ (Fast)** | $O(N)$ (Slow) | $O(1)$ | $O(1)$ |
| **add(item)** (Add to end)| $O(1)$ | $O(1)$ | $O(1)$ | $O(1)$ (push) |
| **add(index, item)** (Insert)| $O(N)$ (Slow) | **$O(1)$ (Fast)** | $O(N)$ | N/A |
| **remove(index)** | $O(N)$ (Slow) | **$O(1)$ (Fast)** | $O(N)$ | $O(1)$ (pop) |
| **Thread-Safe?** | No | No | **Yes** | **Yes** |
| **Internal Data Structure**| Array | Linked Nodes | Array | Array |

*(Note: LinkedList insertion/deletion is O(1) only after you have reached the specific node, traversing there still takes O(N). But inserting at the very Head or Tail is pure O(1).)*

## 7. How to write Code like a Senior Engineer (Polymorphism)

Because they all sign the `List` contract, top engineers declare the variable as a `List`, but instantiate the specific type on the right side. 

This makes it incredibly easy to change your mind later without breaking your code!

```java
import java.util.*;

public class ListShowdown {
    public static void main(String[] args) {
        
        // GOOD PRACTICE: Use "List" on the left side.
        
        // Scenario A: We need to do a lot of searching and reading.
        List<String> names = new ArrayList<>();
        names.add("Alice");
        
        // Scenario B: We realize we actually need to do a lot of inserting/deleting!
        // Because we used 'List' on the left, we only have to change ONE word.
        List<String> betterNames = new LinkedList<>(); 
        betterNames.add("Alice"); // The add() method still works perfectly!
        
        // Scenario C: Legacy multi-threading (rarely used)
        List<String> safeNames = new Vector<>();
        
        // Stack is usually declared specifically as a Deque today, not a List
        Deque<String> modernStack = new ArrayDeque<>();
    }
}
```

## 8. FAANG Cheatsheet: Which one should I choose?

If the interviewer asks which one to use, use this logic:

1. **Do you need a LIFO (Last In, First Out) structure?**
   * *Answer:* I need a **Stack** (but I will implement it using `ArrayDeque` for better performance).
2. **Do you need to insert and delete data frequently at the beginning or middle of the list?**
   * *Answer:* I will use a **LinkedList**.
3. **Do you have multiple threads accessing the data at the exact same time?**
   * *Answer:* I could use a **Vector**, but ideally, I would use `Collections.synchronizedList(new ArrayList<>())` or `CopyOnWriteArrayList` in modern Java.
4. **For 95% of other situations (Storing data, looping through it, reading it randomly)?**
   * *Answer:* I will use an **ArrayList**. It is the default, fastest choice for general purpose storage.
