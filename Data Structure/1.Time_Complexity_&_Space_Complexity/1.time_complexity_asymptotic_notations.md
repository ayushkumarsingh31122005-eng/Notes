# 🚀 Time Complexity and Asymptotic Notations

## 1. What is Time Complexity?

Imagine you are looking for a specific book in a library. 
*   If there are 10 books, you can find it very quickly.
*   If there are 10,000 books, it will take much longer.

**Time Complexity** is a way to describe **how the runtime of a program increases as the size of the input increases**. We don't measure time in seconds or minutes because every computer is different (a gaming PC is faster than an old laptop). Instead, we measure time by counting the **number of operations** the program has to do.

Let's call our input size `$n$`. If we give our program an array of 10 items, `$n = 10$`.

---

## 2. Asymptotic Notations: The Mathematical Language

To talk about Time Complexity, computer scientists use "Asymptotic Notations". These are mathematical tools used to represent the time complexity of algorithms. Think of them as different ways to answer the question: *"How long will this take?"*

There are three main notations you need to know:
1.  **Big O Notation ($O$)** -> Worst-Case Scenario
2.  **Omega Notation ($\Omega$)** -> Best-Case Scenario
3.  **Theta Notation ($\Theta$)** -> Exact/Average Scenario

Here is a visual representation of how they relate to the actual time your program takes:

```text
    Time ↑
         |      $O(n)$ : Big O (Upper Bound - Worst Case)
         |     /
         |    /   $\Theta(n)$ : Theta (Tight Bound - Exact/Average Case)
         |   /  /
         |  /  /    $\Omega(n)$ : Omega (Lower Bound - Best Case)
         | /  /   /
         |/  /  /
         +---------------------------------→ Input Size ($n$)
```

Let's explore each one with simple Java examples.

---

### A. Big O Notation ($O$) - The Upper Bound

**What it means:** This describes the **worst-case scenario**. It gives us a maximum limit on how long the algorithm will take. It guarantees that our program will *never* take longer than this. 

*Analogy:* "Finding that book will take me **at most** 10 minutes."

**Java Example:**
Imagine we are searching for a specific number in an array.

```java
public class SearchExample {
    // We are looking for a 'target' number in an 'array'
    public static boolean findNumber(int[] array, int target) {
        // We look at every single number one by one
        for (int i = 0; i < array.length; i++) {
            if (array[i] == target) {
                return true; // Found it!
            }
        }
        return false; // Not found
    }
}
```

**Explanation:** What is the worst-case scenario here? The worst case is that the `target` number is at the very end of the array, or not in the array at all! We would have to check every single item.
If the array size is `$n$`, we do `$n$` checks.
**Time Complexity:** `$O(n)$` (Linear Time).
**Always avoid** : const. values and lower values while calculating wost case.(since adding smaller or constant values to the larger values doesn't impact  much.)

---

### B. Omega Notation ($\Omega$) - The Lower Bound

**What it means:** This describes the **best-case scenario**. It gives us a minimum limit. It guarantees that our program will take *at least* this amount of time.

*Analogy:* "Finding that book will take me **at least** 1 minute."

**Using the previous Java Example:**
Let's look at the exact same `findNumber` code above. 

**Explanation:** What is the absolute best thing that could happen? The `target` number is the very first item in the array! The loop runs only exactly 1 time, no matter if the array has 10 items or 1 million items.
**Time Complexity:** `$\Omega(1)$` (Constant Time).

---

### C. Theta Notation ($\Theta$) - The Tight Bound

**What it means:** This describes the **average or exact scenario**. It means the algorithm behaves the same way for both the upper and lower bounds. If an algorithm is `$O(n)$` and `$\Omega(n)$`, then it is `$\Theta(n)$`.

*Analogy:* "Finding that book will take me **exactly** 5 minutes."

**Java Example:**
Let's look at a program that *always* takes the same amount of time relative to the input, regardless of what the data actually is.

```java
public class PrintExample {
    // We want to print every number in the array
    public static void printAll(int[] array) {
        for (int i = 0; i < array.length; i++) {
            System.out.println(array[i]);
        }
    }
}
```

**Explanation:** In this code, there is no "best" or "worst" case. If the array size is `$n$`, the `System.out.println` runs exactly `$n$` times. It always loops through the entire array.
**Time Complexity:** `$\Theta(n)$`.

---

## 3. Summary of Common Complexities (From Fastest to Slowest)

1.  **$O(1)$ - Constant Time:** Extremely fast. Takes the same time regardless of input size (e.g., getting the first item of an array).
2.  **$O(\log n)$ - Logarithmic Time:** Very fast. Halves the input every step (e.g., Binary Search).
3.  **$O(n)$ - Linear Time:** Fairly fast. Time increases directly with input size (e.g., a simple `for` loop).
4.  **$O(n^2)$ - Quadratic Time:** Slow. Usually caused by nested loops (a loop inside a loop). Try to avoid this for large inputs!

### Final Teacher's Tip:
In the industry, when we talk during interviews or design software, we usually only care about the **Big O Notation ($O$)**. Why? Because as programmers, we must always prepare for the worst-case scenario!
